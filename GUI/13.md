# 第 13 步：實作 Extension / MCP 管理畫面

## 目標

重用既有`ExtensionManager`的scan、model plan、exact binding approval、apply與restart semantics，提供結構化GUI而不放寬任何trust boundary。

## 頁面狀態

### Status（不呼叫模型）

- drop-in root。
- managed state root。
- desired/applied counts。
- applied vs running revision。
- restart required。
- manager available/error。
- running MCP families。
- startup/scan diagnostics。

頁面初開只跑Status，不自動Preview，避免意外OpenRouter call。

### Preview（明確使用者動作）

按鈕文案需說：

- 會重新scan本機drop-ins。
- 有changes時會呼叫目前chat model產生隔離管理plan。
- 可能耗時並產生API使用量。
- 不會install/build/download，也不會立即套用。

Sync `preview()`用thread offload執行，期間鎖住另一extension operation。

## Preview DTO

每個item顯示：

- key、kind、authoritative operation（add/update/delete/blocked/guarded）。
- model decision/summary/reason。
- source hash與validation diagnostics（適度縮短顯示）。
- host block reason。
- MCP candidate時：family、scope、transport、resolved command、argv、cwd、env binding names/required、binding hash。

不回傳environment secret values、bundle full contents或private management skill文字。

完整`ExtensionPreview`只存在Python memory，以opaque `previewId`查找。

## Approval UX

- Skill add/update/delete：一個整體apply confirmation可涵蓋，但完整items先可見。
- 每個MCP command binding各自checkbox/approval control。
- Exact command/argv/cwd/env sources與binding hash全部可檢閱。
- 未勾選binding傳不到`approved_mcp_bindings`，結果應是`pending_approval`而非偷偷套用。
- Blocked/guarded item永遠不能被frontend override。

## Apply

1. Frontend傳preview ID與approved binding hashes。
2. Python使用原`ExtensionPreview`呼叫manager apply。
3. Manager自身重查registry revision、private skill hash、drop-in diff與binding。
4. GUI顯示逐項`added/updated/removed/blocked/pending_approval/unchanged`。
5. Revision改變時顯示persistent restart banner。

Apply後consume preview ID；retry前必須重新Preview。

## Restart

- Apply不hot reload目前session。
- `Restart backend`先走第07步flush/shutdown，再建立新backend/session。
- Restart後重新status，確認running revision等於applied revision。
- 若restart失敗，applied registry仍保留；UI顯示backend problem，不回滾registry。

## 既有技術債的呈現

- Issue 02：startup後managed Skill被外部process改寫的完整性缺口仍存在；GUI不宣稱session snapshot不可變。
- Issue 04：apply lock是process-local；單GUI backend能避免本app重入，但另一CLI process仍可能race。UI可顯示「套用時請勿在另一CLI同時操作」，不在本step修cross-process lock。
- `tool/local/` v1不載入，UI不顯示成可安裝工具。

## Busy policy

- Active turn、KB mutation、shutdown時拒絕preview/apply。
- Preview/apply時拒絕新turn與backend restart。
- Status可在idle讀；是否允許running讀取依實測安全性，最小版只在idle。

## Tests

- Status不建model／不發provider call。
- Preview zero changes不呼叫model。
- Preview safe DTO不含secret/private skill。
- Unknown/stale/replayed preview ID拒絕。
- 每bindingapproval精準映射。
- Drop-in/revision變更要求re-preview。
- Apply結果與restart required。
- Restart後new skill/MCP才出現。
- 重用`test_extension_user_journey.py`的temp roots/fake model。

## 驗收條件

- GUI能完成現有dry-run/preview→approval→apply→restart journey。
- 沒有繞過manager host validation或binding hash。
- 未批准的MCP絕不執行／標為approved。
- 畫面清楚區分desired、applied、running三個狀態。
