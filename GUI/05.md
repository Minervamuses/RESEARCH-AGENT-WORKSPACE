# 第 05 步：建立 Python desktop bridge 與 application service

## 目標

新增一個只屬於 `agent` application layer 的 desktop adapter，讓 GUI 能用結構化 methods 呼叫現有 `ChatSession`、RAG 與 extensions，同時不讓 `rag` 反向依賴 Tauri/agent。

## 批准閘門

這一步會新增 production package，且後續可能需觸及超過三個 production files。正式實作前要再次列出確切檔案與最小改動，取得使用者批准。

## 建議目錄

```text
app/agent/desktop/
├── __init__.py
├── protocol.py      # envelopes/DTO validation
├── service.py       # application methods、locks、error mapping
├── server.py        # stdin reader、stdout writer、main entrypoint
└── approvals.py     # 第 09 步才加入實作
```

不要建立 generic plugin/RPC framework；若三個檔案已能保持可讀，就不再拆分。

## Process 啟動順序

1. `server.main()` 先執行 `require_conda_runtime("app")`。
2. 固定 cwd 為 `find_app_root()`，但保留原 cwd 在 diagnostics。
3. 啟動單一長壽命 asyncio loop。
4. 建立 protocol reader/writer 與 `DesktopService`，此時不急著建 `ChatSession`。
5. 發 `backend.ready`，讓缺 OpenRouter key 的使用者仍可開 Diagnostics。
6. 收到 `session.create` 才呼叫 `ChatSession.create()`。

## 為何 session 不在 process startup 自動建立

`ChatSession.create()` 會建立主模型並載入 MCP；缺 `OPENROUTER_API_KEY` 時可能 fail-fast。Backend process readiness 與 chat session readiness 必須分開，否則 GUI 只會看到「process crash」，無法顯示可採取的設定動作。

## DesktopService 狀態

- `session: ChatSession | None`
- `lifecycle: starting | ready | shutting_down | stopped`
- 一個 active turn job。
- 一把 knowledge mutation lock。
- 一把 extension operation lock。
- server-side extension preview cache：opaque ID → `ExtensionPreview`。
- request event sequence counters。
- 第 09 步的 pending approvals registry。

只保留必要的 in-memory state；不把 request history 或完整 transcript另寫新 database。

## Session methods

### `session.create`

- Whitelist params：`loadMcp: bool`、可選的 validated `graphRecursionLimit`。
- 不接受任意 `AgentConfig` dictionary。
- 回傳結構化 session snapshot、loaded skills、MCP families、startup diagnostics。
- 已有 session 時拒絕，除非先完成明確 restart/shutdown。

### `session.turn`

- 驗證 non-empty text 與合理長度。
- 呼叫 `turn_outcome()`，不是 `turn()`，保留 validation errors/tool summaries。
- 只在 Python 層產生 server turn ID。
- 未處理例外轉 stable error；不能照 CLI 把 exception字串偽裝成已記錄 assistant answer。

### Mode/skill methods

- 直接呼叫 `enter_plan_mode`、`exit_plan_mode`、`set_thinking_mode`、`activate_skill`、`deactivate_skill`。
- 在 active turn期間由 service拒絕 mutation。
- 每次成功後回新的 snapshot，frontend不自行推測副作用。

### `session.shutdown`

- 停止新 work。
- 若無 active turn，呼叫 `flush_recent_turns()`。
- Flush 失敗要回 `SHUTDOWN_FLUSH_FAILED`，不可只記 warning。
- 清除 session-local preview/approval state。

## Knowledge methods

- Read methods只呼叫公開 `rag` APIs並轉 DTO。
- `list_chunks` 在 adapter 提供 `offset/limit`（例如 limit上限 100），但文件要承認底層目前仍載入整份 `raw.json`。
- Mutation methods只透過 `agent.ingest`／`rag` host APIs。
- 同時間只允許一個 KB mutation；第一版也保守拒絕 mutation期間的 semantic search。
- 不允許 React指定 embedding model/chunk settings；避免既有 store維度／設定漂移。

## Extension methods

- `status()` 可隨時以 thread offload呼叫，不需要模型。
- `preview()` 是 sync且會呼叫模型，使用 `asyncio.to_thread()`。
- 完整 `ExtensionPreview` 留在 backend；回傳 safe DTO與 `previewId`。
- `apply(previewId, approvedBindingHashes)` 使用同一物件；unknown/stale ID拒絕。
- Apply terminal 後 consume preview ID，防止重播。

## Protocol server concurrency

- Stdin reader不能在處理一個長 request期間停止讀取，否則第 09 步 approval response會死鎖。
- 建議用 dedicated reader task/thread解析完整行，再投遞到 asyncio loop。
- 每個 request有 task，但 service locks仍 enforcement domain互斥。
- Stdout只有一個序列化 writer；progress callback只快速 enqueue，不直接做阻塞 I/O。
- Malformed JSON產生 protocol error；無法取得 request ID時可發 process-level error，不讓 server因單行壞資料崩潰。

## Stdout discipline

- Backend domain execution不得有 incidental `print()` 到 stdout。
- Python logging handler統一到 stderr。
- RAG ingest 的現有 print在第 12 步改成 callback前，不得透過 JSONL backend執行。
- 加測試：每個 service method執行後，stdout每一行都必須是合法 envelope。

## Error mapping

Adapter只映射可辨識的 runtime/domain failures；unknown exception轉 `INTERNAL_ERROR`。

至少區分：

- Conda guard failure。
- OpenRouter key absent/model init failure。
- Ollama connection/model failure。
- graph recursion hard error。
- invalid mode/skill/task mode。
- path missing/refused/sentinel。
- Chroma/JSON external-write conflict。
- extension preview/apply errors。
- busy/lifecycle errors。

不為 `rag` 建一個全新 typed exception hierarchy；先在 GUI integration boundary做最小分類。

## 測試

- 用現有 `FakeChatSession`／fake history/model，不發 live provider call。
- Session create成功／失敗與 retry。
- 單 turn、busy second turn、mode mutation busy拒絕。
- Shutdown一定呼叫 flush，flush failure有結構化結果。
- Extension preview object不跨 wire且不能重播。
- Invalid path/config field拒絕。
- Unicode與大回答仍為一行合法 JSON。

## 驗收條件

- `python -m agent.desktop.server` 在正確 Conda env可 handshake。
- 缺 OpenRouter key時 backend仍 alive且 Diagnostics可用。
- 不 import CLI handlers、不解析 CLI文字。
- `rag` package沒有新增 `agent`/desktop import。
- 所有 persistent mutation仍由現有 Python domain code完成。
