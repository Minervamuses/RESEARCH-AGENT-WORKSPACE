# 第 10 步：實作 Mode、Thinking、Skills 與 Citation controls

## 目標

把目前slash commands背後的session methods變成明確GUI controls，完整保留互斥與state teardown規則，不讓frontend自行猜副作用。

## 共通規則

- 只有session ready且idle時可變更。
- 所有請求經Python service再次檢查busy state。
- 成功response一定回傳完整新snapshot；frontend以snapshot為準。
- 失敗不做optimistic state commit。
- GUI不把slash字串送進CLI parser。

## Plan mode

### UI

- Segmented control：`一般` / `計劃`。
- 切到計劃後顯示新`plan_log_path`。
- 顯示固定說明：plan turns寫Markdown、不進chat-history Chroma、`recall_history`查不到。
- 提供copy path；「在檔案管理器顯示」若需opener plugin，另行dependency批准，不在此步強加。

### Backend

- `plan` → `enter_plan_mode()`。
- `normal` → `exit_plan_mode()`。
- 重複設定同mode應idempotent或回目前狀態。
- 不另建第二份plan檔或GUI autosave。

## Thinking mode

### UI

- Radio/segmented control：Normal、Extended。
- Extended旁明示：更多模型呼叫、可能較慢，沒有整turn cancel保證。
- Model slots未設定或session拒絕時，顯示具體缺少欄位／provider failure。
- Citation active時Extended disabled並顯示原因。

### Backend

- 只接受`normal|extended`。
- 呼叫`set_thinking_mode()`，沿用citation互斥。
- 不開放前端任意修改reviewer/rewrite/fusion models。
- 不重新引入已刪除的tool-budget slider；若顯示graph limit，要叫`supersteps emergency limit`。

## Skills

### Catalog DTO

- name。
- description。
- available task modes。
- built-in/applied來源（能可靠判定才顯示）。
- active/task mode。
- activation availability與error。

不要把完整SKILL.md/pinned references送到frontend。

### UI

- 同時只選一個active skill，另有`None`。
- 有task modes時先選mode，再activation。
- `academic-paper-writing`顯示四個manifest modes。
- `_prompt-master`標成internal/advanced，不作首頁推薦；不修改discovery schema只為隱藏它。
- Activation失敗保留先前skill，符合現有session行為。

### Lifecycle

- Skill catalog在session startup固定；extension apply後直到restart才更新。
- 切換skill是replace，不保留restoration stack。
- Applied skill在session期間的known integrity debt（issue 02）不因GUI消失；不要宣稱immutable snapshot。

## Citation

### Quick control

- `Citation mode` toggle等價於activate/deactivate citation skill。
- 啟用時顯示：thinking自動回normal、session-local source registry開始。
- 停用／切其他skill時顯示：registry會清除，但已寫入`cite/` bundles保留。
- Citation active時可用普通composer提問；不需要另做一套citation chat engine。

### Final output

- 只呈現Python finalizer/gate/render後的`TurnOutcome.text`。
- Frontend不解析`[[cite:...]]`來自行重排或驗證。
- `validation_errors`作安全notice，不顯示被阻擋的原draft。
- Save結果若未有結構化safe DTO，就只顯示tool returned與final answer；不可解析CLI/stdout。

### Saved sources邊界

- 現有registry只代表本次citation session，停用/restart即消失。
- Existing disk bundles沒有inventory/rehydrate API。
- 第一版不做「全部Saved citations」archive browser；若未來要做，需新的Python只讀API並在第18步另行批准。
- `version_kind=earliest`的同年/缺日期問題（issue 03）仍存在，UI不得加`已證實最早版本`之類保證。

## Status同步

每次mode/skill mutation後驗證：

- plan mode與log path。
- thinking mode。
- active skill/task mode。
- effective tool names只回安全摘要，不需要全args。
- extension revision/MCP diagnostics保持一致。

## Tests

- Busy turn期間全部mutation被backend拒絕。
- Plan enter/exit與path。
- Extended配置failure、citation互斥。
- Citation activation自動normal。
- Citation deactivation/skill switch觸發registry reset（沿用既有tests）。
- Failed skill activation保留previous active skill。
- Applied extension需restart才出現在catalog。
- Frontend reducer以server snapshot修正optimistic UI。

## 驗收條件

- 使用者不輸入slash command也能完成現有mode/thinking/skill流程。
- 所有互斥都由Python enforcement，不只disabled button。
- Plan/citation persistence說明正確。
- UI不暴露full skill instructions或虛構citation archive。
