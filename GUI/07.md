# 第 07 步：完成 readiness、診斷與 graceful shutdown

## 目標

把「Tauri window存在」、「Python backend可用」、「ChatSession可用」、「外部服務可用」分成可理解狀態，並在正常關閉時保護 recent turns。

## 狀態機

```text
desktop_starting
  → backend_starting
  → backend_ready
  → session_starting
  → session_ready
  → shutting_down
  → stopped

任一階段可進 degraded 或 crashed；degraded不等於整個app不能用。
```

## Runtime diagnostics DTO

### Runtime identity

- OS/platform（必須是 Linux）。
- app root與backend cwd。
- Python version、`sys.prefix`、Conda env name/path。
- protocol version與backend build/version。
- Node/Rust version只屬build diagnostics，不要求Python runtime自行探測。

### Configuration presence

- `OPENROUTER_API_KEY`: configured boolean。
- `OPENALEX_API_KEY`: configured boolean。
- `KMS_STORE_DIR`：resolved path，可顯示但不可由frontend任意熱改。
- `CITATION_OUTPUT_DIR`：resolved path。
- MCP enable flags與resolved families，不回 secret values。

### Local services

- Ollama reachable。
- `bge-m3` model present。
- OpenRouter不在startup自動發付費／驗證call；只檢查key presence與session建立結果。
- MCP逐family顯示 loaded/degraded與startup diagnostic。

Ollama探測要有短timeout，失敗不拖住整個UI。若沒有穩定的typed probe，先只顯示「unchecked」與實際操作錯誤，不寫假綠燈。

## Session create flow

1. Backend ready後frontend讀 diagnostics。
2. 必要條件具備時呼叫 `session.create`。
3. 顯示 skills/extensions/MCP startup progress。
4. MCP單一failure不讓session失敗；回 degraded family。
5. Main model/OpenRouter初始化failure則session未ready，但backend繼續服務Diagnostics與restart。
6. Retry會建立全新session attempt，不重用半初始化object。

## Graceful shutdown flow

### Idle

1. Frontend停止接受新actions。
2. `session.shutdown`呼叫 `flush_recent_turns()`。
3. 關閉session-scoped resources與可關閉的provider/MCP resources。
4. Python發shutdown result後結束。
5. Rust等待child exit，再關Tauri。

### Active turn / mutation

第一版沒有可靠cancel：

- 預設顯示「正在完成目前工作後關閉」。
- 使用者可返回app繼續等待。
- 另提供`Force quit`，必須再次確認可能遺失recent turns或留下partial ingest。
- 不可把關閉window直接當作 task cancellation成功。

### Flush failure

- 顯示 `SHUTDOWN_FLUSH_FAILED`、尚未flush turn count與safe原因。
- 提供 `Retry flush`、`Return to app`、`Force quit`。
- 不在失敗後自動kill。

## Plan/citation特殊狀態

- Plan turns已逐turn寫Markdown，但當次寫入若失敗，turn本身應已失敗；shutdown仍回報recent flush狀態。
- Citation bundle已保存的不會因session shutdown刪除。
- Citation source registry會消失，frontend重啟後不得沿用舊source cards為active registry。

## Backend restart

只允許在idle：

1. Flush目前session。
2. Gracefully stop Python。
3. Rust啟新process、重新handshake。
4. 建立新session並讀新extension revision。
5. UI清楚分隔舊transcript為「previous local view」或直接清空；不能送舊session continuation。

第一版建議清空live transcript，避免誤解已恢復context；若保留視覺內容，必須不可互動且有明顯分隔。

## 測試

- Key missing仍能進Diagnostics。
- MCP failure→session ready + degraded。
- Session init failure→backend保持ready且可retry。
- Idle shutdown calls flush exactly once。
- Flush failure不退出。
- Active work close不誤報cancelled。
- Unexpected child exit→crashed state與pending cleanup。

## 驗收條件

- 使用者能分辨backend與session readiness。
- 外部服務部分失敗不被統一顯示為「app壞了」。
- 正常關閉有可觀察的flush success。
- Force quit前有具體資料風險說明。
- Backend restart後不宣稱resume舊session。
