# 第 03 步：建立最小 Tauri 2 + React + TypeScript 骨架

## 目標

只建立可開啟的 Linux desktop shell，驗證 WebKitGTK、Vite 與 Tauri 組合。此步不接 Python、不做 chat、不讀寫 store。

## 前置條件

- 第 02 步所有 dependency 已獲批准並驗證。
- Git working tree 狀態已重新確認；不碰使用者既有改動。

## 建議目錄

```text
app/
└── desktop/
    ├── package.json
    ├── package-lock.json
    ├── tsconfig*.json
    ├── vite.config.ts
    ├── index.html
    ├── src/
    │   ├── main.tsx
    │   ├── App.tsx
    │   └── styles/
    └── src-tauri/
        ├── Cargo.toml
        ├── Cargo.lock
        ├── build.rs
        ├── tauri.conf.json
        ├── capabilities/
        └── src/
            ├── main.rs
            └── lib.rs
```

規劃文件的根目錄 `GUI/` 與實際程式的 `app/desktop/` 刻意分開，避免 Linux 大小寫目錄與 Windows tooling 混淆。

## Scaffold 原則

- Vite SPA，不用 SSR/meta-framework。
- React functional components + TypeScript strict mode。
- 一個 `main` window；不做 tray、多視窗、deep link。
- npm scripts 只保留 `dev`、`build`、`test`、`tauri` 等實際會用的入口。
- `vite.config.ts` 使用固定 dev port、`strictPort`、忽略 `src-tauri` watch。
- source map 僅 debug；production 使用 bundled local assets。
- 一開始就以繁中 lang attribute、合理 viewport 與可縮放字體建立基線。

官方參考：[Tauri Vite configuration](https://v2.tauri.app/start/frontend/vite/)。

## 最小權限

- `main` window 只取得必要 core invoke/channel 能力。
- 此步不啟用 shell、filesystem、HTTP、notification、updater。
- Dialog plugin 即使已安裝，也只在 Knowledge feature完成時才啟用需要的 open permission。
- 設置 CSP：`default-src 'self'`，connect 僅 Tauri IPC/dev server 必需來源；不允許 CDN scripts。

## 第一個畫面

只顯示：

- App title。
- `Desktop shell ready`。
- Tauri version／platform 的非敏感資訊。
- 四個 disabled navigation placeholders。

不要在這一步先寫 fake chat data、fake settings 或 mock production workflow。

## 預計變更範圍

- 全部新增檔案只在 `app/desktop/`。
- 不修改 `app/agent/`、`app/rag/`、`app/skills/`、`app/pyproject.toml`。
- 若需要補 `.gitignore`，只能加入 `app/desktop/node_modules/`、frontend `dist/`、Cargo `target/` 等生成物，先確認現有規則是否已涵蓋。

## 驗證

```bash
cd app/desktop
npm run build
npm run tauri dev
```

第一個 command 驗證 TypeScript/Vite；第二個透過 WSLg 開一個真實 Tauri window。首次 Cargo build 較慢，不因等待而啟動其他架構工作。

## 驗收條件

- Linux Tauri window 在 WSLg 正常顯示與關閉。
- Frontend production build 成功。
- CSP／capability 檔存在且沒有 broad shell/fs grant。
- Git diff 只包含 scaffold 與必要 ignore 規則。
- 沒有 Python process、localhost server、store write 或 provider call。

## 停止點

完成這個空殼就停止。只有 UI shell 本身在 WSLg 穩定後，才進入 wire protocol；不要同一 commit 順便接 ChatSession。
