# 第 14 步：統一錯誤、degraded state、recovery 與觀測

## 目標

讓常見失敗變成使用者可行動的結構化狀態，同時保留本機debug證據；不把raw exception、secret或MCP不可信stderr直接丟進UI。

## 三層錯誤

### 1. User/action error

可重試、輸入錯誤或前置條件不足，例如invalid path、missing key、Ollama offline、busy。

UI顯示：發生什麼、哪項功能受影響、下一步。保留stable code可copy。

### 2. Degraded capability

App/session仍可運作，但部分能力不可用，例如MCP family load失敗、Ollama offline使semantic search/recall不可用。

UI顯示badge與Diagnostics detail，不用全畫面fatal error。

### 3. Fatal backend/protocol error

Child crash、unsupported protocol、stdout framing corrupt、wrong Conda runtime。

停止新work、fail pending requests、顯示restart/exit選項。

## Error mapping表

| Code | 使用者訊息重點 | 建議動作 |
|---|---|---|
| `RUNTIME_WRONG_CONDA_ENV` | Python不是Conda `app` | 從正確env啟動 |
| `OPENROUTER_NOT_CONFIGURED` | Chat/folder tagging不可用 | 設定Conda env var後restart |
| `OLLAMA_UNREACHABLE` | Search/embedding不可用 | 啟動Ollama |
| `OLLAMA_MODEL_MISSING` | 缺`bge-m3` | 明確執行pull（GUI不自動） |
| `GRAPH_LIMIT_REACHED` | 回合未正常收斂 | 縮小問題；顯示是否已有best-effort answer |
| `BUSY_*` | 另一工作進行中 | 等待完成 |
| `RAG_PARTIAL_WRITE_POSSIBLE` | Ingest可能只完成部分雙寫 | 修正原因後重跑同root |
| `PRUNE_PREVIEW_STALE` | Preview後內容改變 | 重新Preview |
| `EXTENSION_*` | scan/model/apply某階段失敗 | 保留revision，重新status/preview |
| `SHUTDOWN_FLUSH_FAILED` | recent turns未全持久化 | retry/return/force quit |
| `PROTOCOL_*` | frontend/backend不相容或資料損壞 | restart；必要時重建同版本 |

## Recovery notices vs failures

現有graph可能：

- retry空模型response。
- 在recursion limit前強制finalize。
- 修復tool-protocol artifact。
- 產生deterministic fallback。

若`TurnOutcome`成功，final answer仍應顯示；另用small notice呈現recovery metadata。不要把每次內部retry都當error modal。

## Logging

### Python stderr

- 使用既有logging與新增desktop component logger。
- 不log API key、env values、full user prompt、full tool result。
- Request ID、session ID、turn ID、method、duration、terminal status可log。
- Traceback只在local log，不跨default DTO。

### Rust

- 記child lifecycle、protocol parse/code、pending cleanup。
- Stderr採bounded ring或rotate local log；容量小且明確。
- Arbitrary MCP/backend stderr預設不直接顯示WebView。

### Frontend

- Production不console.log完整protocol payload。
- Error boundary捕捉render failure，提供reload UI；reload前提醒backend/session狀態。

本專案不新增remote telemetry、crash upload或analytics。

## Retry policy

- Read requests可明確user retry。
- Session create可在修正env後backend restart再retry。
- Turn failure不自動重送，避免重複provider/tool mutation。
- Ingest/prune/extension apply不自動retry。
- Protocol write failure不自動replaymutating request。
- Approval response不可retry成執行。

## Durations與timeout

- UI顯示elapsed，不推測remaining time。
- Extended candidate已有內部timeout，不把它誤當整turn timeout。
- Ollama diagnostics使用短timeout。
- Backend request若超過UI soft threshold只顯示still running；不自行cancel。
- Force kill只在user confirmation後。

## Tests

- 每個known exception映射到穩定code且不含secret。
- Unknown exception只回safe message與correlation ID。
- Success with recovery不是failure。
- Mutating request transport failure不被自動重播。
- Degraded MCP/Ollama只影響相應功能。
- Stderr injection不成為HTML或protocol event。

## 驗收條件

- 常見runtime/service/store failures都有可行動繁中訊息。
- UI不顯示raw traceback、key、完整tool payload。
- Backend crash能清理pending requests並安全restart。
- 沒有remote logging或新service。
