# 第 06 步：建立 Rust process supervisor 與 Tauri IPC

## 目標

讓 Tauri/Rust 安全地擁有 Python child lifecycle，並把 React的 typed commands/Channels橋接到第 04/05 步的 NDJSON protocol。

## 架構選擇

Phase 1不把 Python打成 bundled sidecar。Rust從已啟用的 Conda `app` environment繼承 PATH，執行：

```text
python -m agent.desktop.server
```

工作目錄固定為 `app/`。不可硬編碼 `/home/minervamuses/miniconda3`；若 `python` 不符合 backend的 Conda guard，讓 handshake明確失敗。

Tauri官方 external binary機制需要 target-specific executable，適合未來真正 bundle後再用：[Embedding External Binaries](https://v2.tauri.app/develop/sidecar/)。

## Rust AppState

最小狀態：

- child handle / stdin writer。
- background stdout reader task。
- background stderr reader task。
- backend lifecycle state。
- `HashMap<requestId, pending response sender>`。
- frontend Channel（或一個 per-request Channel設計，擇一後固定）。
- bounded, redacted stderr ring buffer metadata。
- shutdown guard。

所有 state放單一 Tauri managed state，不在不同 commands各建 child。

## 對 React公開的 commands

- `backend_start()`
- `backend_connect(channel)`
- `backend_request(envelope)`
- `backend_status()`
- `backend_shutdown(force: bool)`

不要公開 raw `spawn(command,args)` 或 shell command。

## Request flow

1. TypeScript產生 request ID並呼叫 `backend_request`。
2. Rust驗證 backend ready、ID未重複、method在允許集合。
3. Rust登記 pending sender，再把一行 JSON寫入 child stdin並 flush。
4. Stdout reader逐行parse：event送 Channel，terminal result解 pending request。
5. Result／error回到 invoke Promise。
6. Parse failure、unexpected EOF或child exit會 fail所有 pending requests並發 `backend.crashed`。

Rust不是第二次完整 domain validator，但要驗證 envelope shape、size、protocol version與 lifecycle。

## 為何用 Channel

Tauri官方把 Channel定位為 ordered streaming資料的建議機制；全域 events較動態、型別較弱，async listener也可能造成處理順序混亂：[Calling Rust from the Frontend](https://v2.tauri.app/develop/calling-rust/)。

本專案事件量不高，但 ordered progress/approval仍比全域 event更符合 request sequence契約。

## Child stdout/stderr

- Stdout reader只接受合法 protocol line。
- Stderr絕不當 response；預設寫 local Rust log或bounded memory。
- 不把 arbitrary MCP stderr自動推到 WebView，避免secret／不可信文字洩漏。
- Diagnostics只顯示安全摘要（timestamp、level、component、error class），raw log需明確user action才查看。

## Crash/restart

- Child無預期退出：UI進 `crashed`，所有 actions disabled，保留前端live transcript但標示未持久化狀態未知。
- Restart只在沒有 pending graceful shutdown時執行。
- 防 restart loop；自動最多嘗試一次或完全由使用者按鈕觸發，第一版建議後者。
- 新 backend產生新 session；不得把舊 transcript假裝已 resume。

## App close integration

- Window close先 prevent，進第 07步 shutdown flow。
- 正常完成後才 exit Tauri。
- Timeout後的 force kill是明確user action。
- Rust process destructor仍保留最後防線，避免 orphan Python child，但不能取代Python flush。

## Tauri capabilities

- Frontend只取得本 app自有 commands與必要 Channel能力。
- 不給 shell plugin execution/spawn權限。
- Dialog plugin只給 open dialog；選到的path仍須交Python驗證。
- 單一 main window，不允許remote origin呼叫 privileged command。

## Rust tests

- 用小型 fake child script回放 shared protocol fixtures，不啟動真實 agent/provider。
- Partial line、兩行同一read、Unicode、oversized line。
- Event order與terminal correlation。
- Duplicate request ID。
- Malformed stdout導致所有 pending fail。
- Stderr不污染 stdout parser。
- Graceful exit、unexpected exit、force kill。

## 驗收條件

- React能透過一個 harmless diagnostics request來回 Python。
- Ordered events與terminal result不丟失、不重複。
- Backend crash後沒有永久pending Promise或 orphan child。
- WebView沒有任意shell權限。
- Child interpreter由Conda env繼承且通過Python guard。
