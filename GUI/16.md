# 第 16 步：建立分層自動驗證與 Contract Tests

## 目標

用最小但足以區分GUI regression的測試覆蓋Python adapter、NDJSON、Rust supervisor與React state；沿用現有pytest資產，不建立昂貴的全新evaluation framework。

## 現有基線

- Repo有70個`test_*.py`、638個test function definitions；parameterization後case更多。
- 最新checked-in紀錄（不是本輪重跑）是`694 passed, 1 warning`。
- 現有fixtures已有fake history/model/graph/session，可重用。
- 本輪計劃階段沒有執行任何tests。

## 測試金字塔

### A. Python unit/service tests

新增在`app/tests/`，集中於：

- Protocol Pydantic validation。
- DesktopService lifecycle/locks/error mapping。
- ChatSession facade mapping。
- Ingest progress callback與CLI相容。
- Extension preview cache/consume。
- Approval broker（若第09步獲批准）。
- Shutdown flush success/failure。

全部使用temp dirs、fake stores/models/embedders；預設不碰`app/store`、`cite`、plan logs或live network。

### B. Python subprocess contract tests

實際啟動`python -m agent.desktop.server`，但注入fake service或test mode：

- Handshake。
- Multiple requests/events/results。
- Malformed/oversized lines。
- EOF/shutdown。
- Stdout framing purity、stderr isolation。
- Unicode/path spaces。

Test-only injection必須明確且不在production自動啟用；不要靠秘密environment bypass safety。

### C. Rust tests

- Shared fixture parsing。
- Pending request map/order。
- Fake child正常、malformed、crash、hang。
- Stderr isolation。
- Graceful/force shutdown。
- Capability command allowlist可用build-time檢查或review。

### D. TypeScript tests

- Protocol types/guards。
- Reducers與stale sequence/request handling。
- Chat success/failure。
- Mode/skill server snapshot reconciliation。
- Knowledge filters/pagination。
- Extension binding approval selection。
- Approval modal default deny與keyboard。
- Markdown XSS/link sanitization。

只有實際component behavior需要時才加React test utilities；不要先引入Playwright/Cypress完整E2E stack。

## Shared fixtures

放在一個清楚的test fixture目錄，Python/Rust/TS都讀：

- Protocol v1 happy path。
- Error/degraded result。
- Tool progress sequence。
- Approval required/resolved。
- Unsupported version/unknown method。
- Malformed content由各language test本身生成也可。

Fixture不含real key、user data、絕對個人path。

## 必須保留的既有regressions

- CLI finally flush與local slash behavior。
- Graph finalization/recovery。
- Plan write ordering。
- Session eviction/flush failure。
- Citation gate/render/save truth。
- Skill/tool access matrix與PolicyToolNode。
- Bash non-TTY auto-deny。
- Extension full user journey。
- RAG JSON atomic/external write guards。

GUI改造若破壞這些測試，先判斷是direct regression；不要為了讓GUI通過而放寬既有policy。

## 執行順序

開發迴圈：

1. 單一affected Python test module。
2. 單一Rust unit target。
3. 單一frontend test file。
4. Protocol contract group。

接近完成才各跑一次：

```bash
cd app
conda run -n app poetry run pytest

cd app/desktop
npm test -- --run
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
```

實際scripts以scaffold lock定義為準。完整suite若預估超過10分鐘先取得批准；不要無新假設重跑昂貴命令。

## Live services策略

- 自動tests不呼叫OpenRouter、Crossref/DataCite/OpenAlex、MCP remote、Ollama GPU/model。
- 少數real integration放第17步，逐項取得付費／外部call批准。
- 不建立model sweep、benchmark campaign、full-dataset replay。

## 驗收條件

- Tests能抓到protocol drift、wrong request correlation、lost shutdown flush與policy bypass。
- Default test run沒有live paid calls或真實store mutations。
- Existing full pytest suite通過，或任何unrelated failure被清楚分開說明。
- Frontend/Rust production builds通過。
- 不用大而脆弱的GUI E2E framework才能獲得基本信心。
