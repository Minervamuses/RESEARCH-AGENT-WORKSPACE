# 第 01 步：凍結使用者流程與資訊架構

## 目標

在寫程式前先決定第一版 GUI 到底讓使用者完成哪些工作，避免把 CLI 每一行輸出照搬成畫面，或誤造目前不存在的「歷史聊天」能力。

## 前置條件

- 已接受 `00.md` 的 Linux-only、單 backend、單 live session 邊界。
- 此步只產出 UI contract／wireframe，不新增 frontend dependency。

## 建議的四個主區域

### 1. Chat

- 中央：本次啟動的 live transcript。
- 底部：純文字 composer、送出按鈕、busy 狀態。
- 頂部狀態列：Normal/Plan、Normal/Extended、active skill、MCP degraded badge。
- 側欄／drawer：skill 與 task mode、session/status、目前 plan log path。
- 每個 assistant turn：finalized Markdown、validation/recovery notice、折疊式 tool activity。
- 不顯示虛構的「過去 sessions 清單」；backend restart 後只顯示新 live transcript。

### 2. Knowledge

- `Overview`：categories、tags、folder summaries、store path 與 availability。
- `Search`：query、k、folder/category/file type/date filters、hits、context expansion。
- `Documents`：paged chunk inventory；明確標示這是 stored chunks，不是原檔瀏覽器。
- `Manage`：workspace init、single-file/folder ingest、sync、prune。

### 3. Extensions

- Status：drop-in/state roots、desired/applied/running revisions、diagnostics。
- Preview：authoritative diff、manager summary、blocked reasons。
- MCP approval：exact command、argv、cwd、env variable names、binding hash。
- Apply result：逐項結果與 restart-required banner。

### 4. Diagnostics

- Runtime：Linux、app root、Conda env/Python、backend/protocol versions。
- Services：OpenRouter configured、Ollama reachable/model present、MCP loaded/degraded。
- Data：store、plan log、citation output、extension paths。
- Backend：running/busy/crashed、last safe error、restart action。
- Secret 僅顯示 configured/not configured；不回傳內容。

## 核心 user journeys

### Journey A：啟動並聊天

1. App 顯示 backend process readiness。
2. 若缺 OpenRouter key，仍能進 Diagnostics，不建立 chat session。
3. Session 建立成功後顯示 modes、skills、MCP diagnostics。
4. 使用者送出一個 turn；composer 進入 busy，禁止第二次送出。
5. UI 顯示階段／工具活動，finalized outcome 完成後一次顯示答案。
6. 關閉 app 時完成 recent-turn flush。

### Journey B：切 plan / thinking / skill

1. Idle 時才可改 session policy。
2. Plan 開啟後立即顯示新 log path。
3. Extended 顯示「較慢／更多模型呼叫」而不是模糊 slider。
4. Citation active 時 Extended disabled；啟用 citation 會把 thinking 切回 normal。
5. Skill task modes 只顯示 manifest 真正提供的選項。

### Journey C：管理知識庫

1. 先看 readiness，區分「只讀可用」與「semantic search/ingest 需 Ollama」。
2. 檔案／資料夾由 native dialog 選取。
3. Folder ingest 明示會使用 OpenRouter folder tagging；single-file 不會。
4. Ingest 過程鎖住其他 KB mutations，顯示結構化 progress。
5. Sync 只說明 missing-on-disk / missing-in-store，不宣稱偵測 modified files。
6. Prune 必須 preview、比對未變、再次確認後才執行。

### Journey D：套用 extensions

1. Status 不呼叫模型。
2. 使用者主動按 Preview，事前知道這會呼叫 configured chat model。
3. UI 分開顯示 host-authoritative operation 與 model explanation。
4. 每個 MCP binding 各自核准，不能一個籠統「全部同意」。
5. Apply 後保留目前 session、顯示 restart required；使用者主動 restart backend 後才載入新 revision。

## 全域 busy/互斥規則

| 當前狀態 | 允許 | 拒絕或停用 |
|---|---|---|
| Backend starting | Diagnostics shell | session/KB/extension actions |
| Session idle | turn、mode、skill、KB read | 無 |
| Turn running | 查看既有內容 | 第二 turn、mode/skill 切換、extension apply、KB mutation |
| KB mutation running | 查看 transcript/diagnostics | 另一 mutation、semantic search（第一版保守鎖定） |
| Extension preview/apply | 查看其他頁 | turn、另一 preview/apply、backend restart |
| Approval pending | 核准／拒絕該 request | 關閉 modal 後默認執行；任何 late approval |
| Shutdown pending | 查看關閉進度、必要時 force quit | 新工作 |

Python service 必須再次執行這些規則；前端 disabled control 不能作為唯一 enforcement。

## 重要文字與標示

- `Current session only`：transcript 不可恢復。
- `Final response`：不是 token stream。
- `Plan turns are written to Markdown and are not searchable by recall_history.`
- `Search score unavailable`：不顯示偽百分比。
- `Sync checks presence, not file content changes.`
- `Citation sources are session-local; saved bundles remain on disk.`
- `Extension changes load after backend restart.`
- `Force quit may lose unflushed recent turns or leave an ingest partially written.`

正式 UI 文案用繁體中文；必要 technical identifiers（model、tool、path、error code）保留原文。

## Accessibility baseline

- 所有功能可用鍵盤完成；清楚 focus indicator。
- Composer：Enter 送出、Shift+Enter 換行，busy 時不攔截複製／捲動。
- Modal 開啟時 focus trap，關閉後回到觸發 control。
- 狀態不只靠顏色；同時有文字與 icon。
- Progress 以 `aria-live="polite"` 更新，不把每個 node event變成干擾式 announcement。
- Tool details、error stack、path 預設折疊，避免主閱讀流被噪音淹沒。

## 此步產出

- 四頁 navigation 與 responsive wireframe。
- 各 user journey 的 loading/empty/error/success states。
- 全域 busy matrix。
- 繁中 UI glossary。
- 明確列出不提供 thread list、cancel、token stream、attachment。

## 驗收條件

- 每個 control 都能對應到現有 Python method 或後續計劃中的明確 DTO。
- 沒有一個畫面依賴解析 CLI output。
- 沒有畫面暗示可 resume 舊 session、可安全取消 ingest、或已有 similarity score。
- 使用者能從畫面分辨「backend ready」、「session ready」、「service degraded」三種狀態。
