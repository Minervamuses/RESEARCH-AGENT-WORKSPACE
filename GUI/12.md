# 第 12 步：實作 Ingest、Sync、Prune 與結構化進度

## 目標

把host-controlled knowledge mutations做成有路徑驗證、單一mutation lock、真實進度與destructive confirmation的GUI流程，保留現有RAG storage語意。

## 批准閘門

要把repo ingest的`print()`改成結構化callback，將觸及現有production RAG檔。實作前列出最小signature與CLI相容方式並取得批准；不順便重寫雙寫交易或folder metadata格式。

## Path selection

- 使用Tauri官方dialog plugin：[Dialog plugin](https://v2.tauri.app/plugin/dialog/)。
- 因Tauri與Python都在Linux/WSL，dialog回傳Linux path。
- Rust只傳選擇結果；Python做`resolve()`、存在/type/sentinel/skip-dir驗證。
- 不接受Windows `C:\...` path或自動`wslpath`轉換。
- File picker可用既有supported extensions filter，但Python collector仍為權威。

## 三種 ingest

### Workspace init

- 呼叫`agent.ingest.init_workspace()`。
- 明示root是`app/`上層workspace，並排除頂層`app/`。
- 確認顯示resolved root與excluded names後才開始。

### Single file

- 不做OpenRouter folder tagging。
- 顯示pid與chunk count。
- 提醒同名stem pid可能覆蓋既有single-file document；第一版不修改持久schema。
- Unsupported/binary/empty/sentinel得到清楚result。

### Folder/repo

- 明示需要OpenRouter key、Ollama與`bge-m3`。
- 第一版只管理一個intended root；若store已有其他root資料，顯示現有schema無法可靠區分，不提供多root manager。
- 不提供任意chunk/embed model settings。

## Progress callback設計

把`ingest_repo(..., progress=None)`之類的最小optional callback加入framework-neutral RAG。CLI傳console renderer或default console callback，GUI傳event emitter。

事件最少：

- `collecting.started`
- `collecting.completed {folders, files}`
- `tagging.started {total}`
- `tagging.folder_completed {completed,total,folder}`
- `metadata.written {path}`
- `writing.started`
- `writing.file_completed {filePath,chunks,filesCompleted}`
- `ingest.completed {files,chunks}`
- `ingest.failed {stage,partialWritePossible}`

Callback不得傳folder file preview、API payload、完整source text。

現有4-thread tagger completion可能非UI預期順序；sequence以host完成event為準，不假設folder alphabetical progress。

## Cancellation政策

第一版不提供`Cancel ingest`：

- 現有Chroma + JSON是非transactional dual write。
- Sync model calls/thread work未建立cooperative checkpoints。
- 任意取消可能留下partial state，恢復方式是重跑同folder。

Window close時提示等待；force quit明說partial write possible。不要放一顆只cancel frontend Promise的假按鈕。

## Mutation serialization

- Backend一把KB mutation lock涵蓋init/ingest/prune。
- Running時拒絕另一mutation。
- 第一版保守拒絕semantic search，避免讀到中間狀態。
- Completed後clear RAG caches／refresh overview，以現有cache API能安全做到的最小方式處理；不要直接刪generated files。

## Sync

- `list_diff(root)`只顯示：disk not store、store not disk。
- UI文字必須說它只比路徑presence，不比較mtime/hash/content。
- Root必須與原ingest root一致，但現有store沒有保存root可驗證；UI顯示責任提示。
- Sync永不刪除。

## Prune preview/apply

### Preview

- Backend重跑`list_diff`取得orphans。
- 只處理具有`file_path`的repo entries；single-file entries不在範圍。
- 回opaque preview ID、root、sorted orphan list、count與hash。

### Confirm

- Modal顯示root、count與可展開完整list。
- Checkbox/typed confirmation不需要過度複雜；一個明確危險button即可，但default focus在取消。

### Apply

- Backend以preview ID重跑diff。
- 若root或orphan set/hash改變，回`PRUNE_PREVIEW_STALE`，要求重新preview。
- 相同才呼叫`prune_orphans`。
- 回實際deleted list；不要只顯示preview count。
- 不清理stale `folder_meta.json`，除非另有專門issue/批准。

## Failure與恢復

- Tagging phase硬錯誤通常在metadata寫入前中止。
- Metadata、Chroma、raw JSON任何後段failure標示`partialWritePossible`。
- 建議動作是修正service後重跑相同root；不自動wipe store。
- 不提供「重建store」按鈕，因涉及material delete/move。

## Tests

- Existing CLI print行為保持。
- Callback event schema/order與callback failure policy。
- Single mutation lock。
- Path/sentinel/skip-dir拒絕。
- Single-file與folder前置需求差異。
- Sync wording不宣稱modified detection。
- Prune stale preview、no-op、exact deletion。
- Failure event包含正確stage/partial flag。
- 全部使用temp store與fake tagger/embedder，不碰`app/store`、不發live calls。

## 驗收條件

- 真實小型temp fixture可從dialog選取、ingest、search、sync。
- Prune只有在server-side revalidation成功後執行。
- Ingest沒有stdout污染NDJSON。
- Force quit風險、single-root限制與無cancel限制清楚可見。
