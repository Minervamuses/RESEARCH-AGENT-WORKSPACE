# 第 11 步：建立唯讀 Knowledge Browser

## 目標

先完成不改資料的RAG GUI：overview、semantic search、chunk inventory與context。這個步驟可獨立驗證Python→Rust→React資料流，再進入較高風險的ingest/prune。

## 現有API與真實語意

- `explore()`：讀`folder_meta.json`；檔案不存在時回空inventory。
- `search()`：Ollama embedding + Chroma；`score`目前永遠`None`。
- `list_chunks()`：掃整份`raw.json`；沒有native pagination。
- `get_context()`：依pid/chunk id取前後0–3 chunks。
- RAG目前沒有typed exception hierarchy，adapter要在邊界分類。

## Overview頁

顯示：

- resolved store path。
- categories count。
- tags。
- date range（若存在）。
- folder、category、tags、summary列表。
- empty state要區分：
  - `folder_meta.json`不存在／尚無folder ingest。
  - 真正error。

不要從Chroma猜folder summary，也不要把single-file ingest誤顯示成folder inventory。

## Search頁

### Input

- query（必填）。
- k（small bounded select，例如1–20）。
- folder prefix。
- category。
- file type。
- date from/to。

前後端都驗證date格式、k範圍與query長度。

### Result card

- pid、chunk ID。
- file path（若metadata有）。
- category/type/folder/date/tags。
- text excerpt。
- `查看上下文` action。

不顯示相似度百分比、星等或排序解釋，因`Hit.score`沒有值。Folder-prefix過濾可能回少於k筆，empty text應說「目前filter下無結果」，不宣稱store完全沒有相關資料。

## Context drawer

- 呼叫`get_context(pid, chunkId, window)`。
- Target chunk明顯標示。
- 保持chunk order與plain text whitespace。
- Window只允許0–3。
- Missing pid與invalid chunk id顯示不同error。
- 不直接從`file_path`讀原檔；這個畫面只反映stored raw chunks。

## Documents頁

Adapter提供：

- filters：folder prefix、pid、category、file type、date。
- offset/limit，上限100。
- result rows + returned count + `hasMore`。

底層`list_chunks()`仍全載`raw.json`後slice；文件與metrics不能宣稱server-side高效pagination。只有測得大型store bottleneck後，才另行優化public RAG API。

## State與cache

- Frontend可cache最後一次overview/search在memory。
- Store mutation成功後invalidate knowledge caches。
- Backend restart後清cache。
- 不把chunk全文塞進localStorage。
- Search request用request ID避免較舊response蓋掉較新query。

## Error UX

- Ollama offline：Search unavailable，但Overview/Documents/Context若store可讀仍可用。
- Model missing：顯示`bge-m3`與既有安裝指引。
- Empty store：引導到Manage tab，不自動ingest。
- JSON/Chroma error：顯示store path與safe code，不顯示raw traceback。
- External-write fingerprint conflict：要求refresh/retry，不自動覆蓋。

## Tests

- DTO保留所有documented fields與Unicode。
- Overview empty vs error。
- Search filters與no-score UI。
- Context target ordering與window bounds。
- Documents pagination bounds/stale response。
- Ollama failure只降級semantic search。
- UI不直接呼叫Tauri fs或讀SQLite/JSON。

## 驗收條件

- 使用當前既有store可看到1個single-file chunk；`folder_meta.json`缺少時Overview正確顯示空folder inventory。
- Semantic search在Ollama ready時可返回result；offline時其他read views仍可用。
- 沒有任何persistent write。
- 沒有顯示假的score或source absolute path。
