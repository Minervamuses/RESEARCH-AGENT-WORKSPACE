## Boundary rules

- **`agent` and `rag`.** `agent` may import `rag` public APIs and the `rag/types.py` host seam. `rag` never imports `agent` or app Skills.
- **`ChatSession` scope.** `ChatSession` orders the work and holds the lock. It delegates graph execution, thinking, Citation policy, canonical transitions and observability. Desktop-specific policy arrives through injected handlers (`operation_approval_handler`, `bash_approval_handler`, prompt-persisted callback, final-text validator) or private hooks the service sets per turn.
- **Tool existence vs authorization.** These stay separate. `tools.access` resolves the set, the graph binds it, and `PolicyToolNode` re-checks admission and asks the injected consent hook at execution.
- **Skill catalog.** It is fixed for one materialized session. Slash and inline references load runtimes inside the turn lock; Python re-resolves inline references even when React supplies them.
- **Citation ownership.** `app/skills/citation` owns Citation truth and `agent/skills/citation` only the session integration. Web Search stays a separate MCP server; the Citation boundary against it is prompt-level (INV-030).
- **Project-scoped history.** Conversation storage exists only after `workspace.select` opens a project. The catalog owns membership and display names; canonical JSON owns transcript text and `customTitle`.
- **Desktop trust split.** React gathers intent and renders bounded state. Rust owns native process and pipe lifetime and the picker dialogs. Python owns policy, path validation and all persistent domain writes. Disabled frontend controls are not authorization.
- **Protocol ownership.** The contract owns cross-language shapes, limits, origins and request ordering. Python, TypeScript and Rust each reject incompatible messages instead of adapting them.
- **Answer delivery.** Progress, tool, approval and `document.proposed` events never carry answer text; React accepts one terminal `final_only` result per turn.
- **Untrusted text.** It renders through `SafeContent`. Only credential-free absolute HTTP(S) URLs reach the opener, and capabilities grant no shell or filesystem access.
- **Generated material.** Stores, `cite/`, `dist/`, `node_modules`, Rust `target`, caches and extension state are not source. Old Plan logs are neither runtime input nor output; the Plan-log directory support and its four committed stubs were removed in `73c8db1` (FAIL-021).

## Ambiguous or overloaded ownership

- **`DesktopService` (4,229 lines)** composes projects, sessions, documents, approvals, Stop, knowledge and extensions. Keep domain logic in its underlying owners (catalog, documents, repository, session) instead of growing the adapter.
- **`agent/ingest.py`** hosts both RAG wrappers and the turn-wide cancellation scope used by tools, RAG callbacks and the desktop. Its docstring and README now say so (`33bc33f`), but the module name still suggests only ingest.
- **Private session hooks.** The desktop reaches into `ChatSession` through private hooks (`_document_turn_active`, `_set_final_text_validator`, `_citation_policy`, `_skill_installer.bypass_approval`, a per-turn `system_prompt_message`). Session refactors must preserve them or replace them with explicit parameters.
- **Duplicated parsing in React.** React derives `@Skill` references from `session.loadedSkills` and keeps an explicit leading `/citation` first in `composeTurnText`. This duplicates Python parsing for UX. Python stays authoritative and rejects stale references, but the two parsers must agree.
- **Hand-copied contract.** It is maintained four times (JSON plus Python, TypeScript and Rust, including 13 snapshot shapes) without code generation. Trace validation is production code in Python and TypeScript, and test-only in Rust.
- **`bashPermissionMode`** now names the project-wide Permission for every side effect.
- **Unused catalog code.** `DesktopProjectCatalog.rebuild_from_conversations` has no caller, and `_project_epoch` is written but never read.
- **Retry Stop.** The README promises Retry Stop, but `_session_stop` re-raises a cached cleanup error and never retries. Recovery is effectively a backend restart (FAIL-022).
- **Legacy Citation entry.** `activate_citation_skill` keeps legacy persistent semantics but has no production caller; supported entries are `/citation` and `@citation`.
- **`mcp.py`** is both MCP client and process-tree reaper for web_search. Its `/proc` scanning and kill deadlines are part of the tool contract, not incidental cleanup.
- **RAG persistence** is split across `folder_meta.json`, `raw.json` and Chroma, with rerun-based recovery (INV-012).
