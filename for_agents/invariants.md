## Enforcement gaps

- INV-012: prune_orphans does not update folder_meta.json; empty/unreadable re-ingest can retain prior chunks; Chroma/raw/meta writes are not one transaction.
- INV-013: startup verifies installed content once, but SkillMetadata retains only a path and load_skill_runtime rereads mutable disk content.
- INV-014: resolution records usually carry only year, and decide_resolution breaks ties with score/rank/provider.
- INV-015: the enforced topology is source-checkout-only. Wheel/installer asset lookup and standalone bundling are outside the current contract and unverified.
- INV-018: preview/approval state is process-local. It does not make the desktop catalog or extension registry safe for multiple concurrently launched application processes.
- INV-004: PolicyToolNode and trace grouping assume non-empty unique tool-call IDs; duplicate-ID rejection is not directly enforced.
- INV-005: raised provider exceptions in some extended-thinking stages can bypass the common finalizer; tests cover malformed outputs more than raised exceptions.
- INV-009: apply is serialized only inside one Python process; cross-process registry lost updates remain possible.
- Direct desktop `knowledge.init_workspace` and `knowledge.ingest_folder` methods remain declared but deliberately fail; only the composer slash-command route supplies the supported folder-maintenance flow.
- Documentation conflict: README.md says academic-paper-writing forbids bash, while current global-tool policy keeps bash available under every skill with its normal approval gate. The prohibition is instruction-level, not access enforcement.
