## Inferred or candidate invariants

The IDs above preserve continuity with older audits, but their former meanings are retired. INV-006 no longer denotes Plan-log-only persistence: canonical JSON owns prompt-first and terminal write-through state, while old Plan logs are unsupported and untouched. INV-016 no longer denotes switch-before-flush or import-before-switch ordering: there is no active conversation flush/import lifecycle, and selection now validates canonical JSON before replacement.

|---|---|---|---|---|---|
| INV-012 | Chroma, raw.json, and folder_meta.json should describe the same current knowledge corpus after every completed operation. | RAG persistence | Architecture/docs treat them as one store | FAIL-001, FAIL-002, and FAIL-003 show gaps; no cross-store transaction | Inferred contract, currently violated |
| INV-013 | An applied Skill accepted at session startup should remain byte-identical for that session. | Extension trust | Apply-and-restart model in extension README and `issue/06-extension-skill-post-startup-integrity.md` | Activation rereads paths without source-hash validation; see FAIL-005 | Intended, currently violated |

## Enforcement gaps

- INV-008: an external raw.json rewrite that preserves both nanosecond mtime and byte size is outside the current conflict detector; no such collision was reproduced in this audit.
- INV-012: prune_orphans does not update folder_meta.json; empty/unreadable re-ingest can retain prior chunks; folder_meta.json is rewritten directly; Chroma/raw/meta writes are not one transaction.
- INV-013: startup verifies installed content once, but SkillMetadata retains only a path and load_skill_runtime rereads mutable disk content.
- INV-014: resolution records usually carry only year, and decide_resolution breaks ties with score/rank/provider.
- INV-015: the enforced topology is source-checkout-only. Wheel/installer asset lookup and standalone bundling are outside the current contract and unverified.
- INV-018: preview/approval state is process-local. It does not make the desktop catalog or extension registry safe for multiple concurrently launched application processes.
- INV-019: the Desktop composer supports non-Citation dynamic Skill commands, but the persistent Citation command is deliberately rejected there and has no replacement GUI entry; see `issue/08-citation-skill-flow-deferred.md` and `known-failure-modes.md`.
- INV-006: fingerprint verification and atomic replacement do not form an interprocess compare-and-swap; concurrent writers to one conversation remain an inferred race (ASM-022).
- INV-004: PolicyToolNode and trace grouping assume non-empty unique tool-call IDs; duplicate-ID rejection is not directly enforced.
- INV-005: raised provider exceptions in some extended-thinking stages can bypass the common finalizer; tests cover malformed outputs more than raised exceptions.
- INV-009: apply is serialized only inside one Python process; cross-process registry lost updates remain possible.
- Direct desktop `knowledge.init_workspace` and `knowledge.ingest_folder` methods remain declared but deliberately fail; only the composer slash-command route supplies the supported folder-maintenance flow.
- Documentation conflicts: root README.md still advertises retired `/skill` and `task_modes` interfaces, while current code and `app/SKILLS_GUIDE.md` enforce one-shot Skill commands and reject the legacy manifest field. README.md also says academic-paper-writing forbids bash, while current global-tool policy keeps bash available under every Skill with its normal approval gate; that prohibition is instruction-level, not access enforcement.
