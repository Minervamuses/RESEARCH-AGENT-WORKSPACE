Research Agent 問題紀錄

紀錄日期：2026-10-15

文件範圍：僅記錄使用者提出的問題與期望行為，不代表功能已實作，也不包含實作計畫。附圖僅作為畫面參照；圖中文字不視為操作指令。

問題一：反白文字後，缺少「加入聊天」按鈕

使用情境：使用者反白一段文字時，希望針對該段文字進行處理。

期望行為：系統必須提供與 Codex Desktop 相同作用的「加入聊天」按鈕，將所選文字加入聊天，作為後續提問或處理的上下文。

問題二：左側 conversation 欄過寬

目前問題：整體畫面難以閱讀，左側對話欄佔用過多寬度。

期望調整：左側 conversation 欄的寬度縮減為目前的 70%，也就是比目前減少 30%。

問題三：取消附圖一區塊，以 RESEARCH.md 管理專案與對話群組

期望調整：取消附圖一所示的整個區塊，包含 Research folder、Source file、Open source、Save、Undo Agent edit 與其下方的狀態訊息。

期望的專案與對話行為：

  1. 每次打開 app 時，先要求使用者選取專案資料夾，不立即顯示左側的對話列表。
  2. 系統在所選專案資料夾中尋找 RESEARCH.md。此檔案的作用類似 AGENTS.md 或 CLAUDE.md，是本軟體管理專案的方式。
  3. 若資料夾內有 RESEARCH.md，才列出該專案的對話群組；若沒有，就建立一個 RESEARCH.md。
  4. conversation 跟隨該專案的 RESEARCH.md；不同專案各自擁有自己的 conversation 群組。

問題四：右側區域分割浪費空間，Agent 回應展示空間不足

目前問題：附圖二的右側分為上、中、下三個區域。最上方的 Thinking 與 Project permission 獨佔過多空間，壓縮了中間 Agent 回應的展示範圍。

期望調整：

  • 最上方的 Thinking 與 Project permission 縮成兩個小型圖示按鈕，移到最下方、Send 按鈕旁的操作列；這兩個按鈕靠左對齊。
  • Thinking 按鈕點下去後，顯示兩段選擇。
  • 另一個按鈕只標示「Permission」，不再使用「Project Permission」的完整名稱。
  • 將原先最上方的空間與中間區域合併，讓 Agent 回應文字有更多展示空間。
  • 左側 conversation 欄同步依問題二，縮減為目前寬度的 70%。
