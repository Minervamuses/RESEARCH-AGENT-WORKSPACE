# P0｜確認執行起點與必需批准

來源與目標：[GOALS.md](../GOALS.md)。共同設計、批准／成本與失敗處理：[PLANS.md](../PLANS.md)。執行狀態、證據與下一步：[build-log.md](../build-log.md)。本檔只維護階段定義；驗證命令參考 [PLANS.md 第 5 節](../PLANS.md#5-驗證命令與成本界線)。

**目的／涵蓋：** G1～G7 的可執行前提；僅確認影響既定需求的邊界。無前置階段。

1. 重新完成 runtime gate，查看 branch／HEAD／dirty state，核對 [PLANS.md 的基準](../PLANS.md#2-已核對的基準與整合位置) 是否過期。不得自動切分支、建立 worktree、還原或提交。
2. 審閱 A1～A6；把接受的提案記入 [build-log.md](../build-log.md)。如文件格式或預覽選取需求改變，先更新受影響階段。普通 UI 排版細節不需反覆詢問。
3. 列出 P1 所需的最小協定資料（文件識別／版本／範圍／操作結果）及 P2～P3 將增補的引用與權限欄位；確認現有大小限制、未知欄位處理、CLI 舊行為。小型 schema 表更新在 [PLANS.md 的共同設計](../PLANS.md#3-擬採設計與尚待審閱的界線)，不另建設計文件。
4. 提交具體批准項：編輯器依賴與必要 worker、protocol 變更，以及確定需要的持久資料變更。說明新增哪個依賴／欄位、為何較小替代不足、預期安裝／建置成本與維護影響；不把整份計劃當成無限授權。已明確批准的同項不再詢問。
5. 確認可用的離線測試、fixture 啟動及原生 GUI 操作方式；不能操作 WSLg 時，安排使用者執行最後的代表性流程，不以純函式測試替代體感。

**出口：** 既定產品決策不重開；首版範圍、必要依賴／契約授權及驗收入口可追溯。批准未到只阻擋相應修改，可完成其餘唯讀核對。
