# P5｜代表性桌面流程與有證據的效能修整

來源與目標：[GOALS.md](../GOALS.md)。共同設計、批准／成本與失敗處理：[PLANS.md](../PLANS.md)。執行狀態、證據與下一步：[build-log.md](../build-log.md)。本檔只維護階段定義；驗證命令參考 [PLANS.md 第 5 節](../PLANS.md#5-驗證命令與成本界線)。

**依賴：** P1～P4。**涵蓋：** G1，並整體驗收 G2～G7。

先在同一現有研究稿與對話做操作走查，分辨 UI 沒有回饋、刻意禁止操作、以及 provider 尚在執行。若側欄仍有同次操作重複 reconcile／JSON 讀取，做一次局部修正並用現有 fake repository 計數或呼叫路徑證明重複工作減少；不新增持久 cache 或改寫對話格式。

只在新增編輯器／preview／Skill 搜尋確實造成問題時，處理必要的重繪、載入或工作分配。保留現有 memo／lazy import 等修改，不為追求架構整齊重寫。歷史分頁的完整 JSON 讀取、RAG 同名 PID／folder 過濾等鄰近問題，除非阻擋本計劃代表情境，列為後續而不順手修。

**必需走查：** 在 Linux／WSLg 的實際桌面路徑，用一份現有代表稿與現有代表對話完成 S1 的 A～E：Enter 立即有 accepted／pending、滑鼠與輸入有回應、左右面板及選取可操作、多 Skill 能用、指定範圍修改／存檔正確、摘要查找不誇大。工具等待時可閱讀、選取及修改文件，衝突流程因而真實可測。保留單回合執行；切換執行中的對話／同時送出第二回合可維持禁止並清楚解釋，不默默新增並行模型。

不記秒數、不設定毫秒門檻；記錄「操作、看到的回饋、是否仍有可明顯感知的停頓」。若沒有改善，照實記錄，不能用減少呼叫次數代替體感結論。原生 GUI 無法操作時，請使用者完成同一短流程；未完成前不標 G1 通過。
