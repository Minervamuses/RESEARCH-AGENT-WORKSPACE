# P3｜專案層級 Ask／Bypass 一致生效

來源與目標：[GOALS.md](../GOALS.md)。共同設計、批准／成本與失敗處理：[PLANS.md](../PLANS.md)。執行狀態、證據與下一步：[build-log.md](../build-log.md)。本檔只維護階段定義；驗證命令參考 [PLANS.md 第 5 節](../PLANS.md#5-驗證命令與成本界線)。

**依賴：** P2；權限契約與必要持久格式批准。**涵蓋：** G7。

先列現有副作用入口和目前批准點，再把「是否需要詢問」接到共同的回合模式；盡量使用簡單共用判斷，不建立通用權限框架。修正 UI 的 Bash-only 描述、等待中控制狀態與操作結果呈現。

**必需驗收：**

| 操作 | Ask | Bypass |
| --- | --- | --- |
| 文件修改／直接存檔 | 批准該操作後才修改；拒絕保留內容 | 無逐次批准，結果可在檔案檢查 |
| Bash 命令 | 沿用單次請求批准與拒絕 | 略過操作批准，保留執行上下文要求 |
| citation 保存 | 批准保存該批明示候選／目標 | 自動保存，仍驗證來源與重複處理 |
| 索引匯入／prune | 明示來源／預覽目標並批准該操作 | 無第二次人為批准，仍核對預覽有效性／目標 |
| MCP／extension 操作 | 批准具體呼叫、安裝或 binding 動作 | 略過同意步驟，仍做 manifest／binding／可用性檢查 |

使用既有 stub、tmp_path、假 MCP／假命令執行器；不以真刪除、真安裝或付費呼叫測權限。每類至少檢查批准、拒絕、Bypass 的相應結果，避免僅測 UI mode 值。

執行中及等待批准時切換須無效且提示下一回合可改；下一回合採用新模式。**Bypass 下重跑 P1 的版本衝突案例，仍必須由使用者選擇。** 模式不能擴大指定段落的改寫範圍，也不能啟用缺少的工具。既有的防重複批准／重試與 extension lifecycle 測試按新規則更新，不能把正確性測試直接刪掉。

**交付：** 所有已列操作種類有明確授權結果；未接入的入口不能對使用者宣稱已覆蓋。
