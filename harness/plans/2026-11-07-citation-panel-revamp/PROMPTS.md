# 執行與續作入口

## 開始／續作

以下是使用者日後可以直接送出的啟動提示，不是撰寫階段的執行指令。

> **使用者端前提**（給使用者看，不是給執行者的指令）：
> - 執行者不會停下來等你，但宿主對沙箱外指令與連網的權限提示不受本計劃控制。如果希望啟動後離開、回來時已經跑完，請以不逐次詢問的權限模式啟動；否則執行會停在第一個沙箱外的檢查（R1-S2 的完整 pytest），或第一次連網（R3-S1 的 `poetry add`）。
> - 執行可能因為用量上限而中斷；再次送出同一段提示即可續作。

> 執行 harness/plans/2026-11-07-citation-panel-revamp/ 計劃，一次執行到底。先讀適用的 AGENTS.md、[GOALS.md](GOALS.md)、[PLANS.md](PLANS.md)、[build-log.md](build-log.md)，再讀下一個相依已滿足的 build 階段檔。開始工作前，先唯讀核對目前的 GUI 分支、HEAD、工作樹，以及 Conda app 中的工具；以步驟 ID 對照已完成的步驟與 commit；保留與本計劃無關的既有工作。依 PLANS 的執行契約做事，並遵守以下要求：
>
> - **我送出這段提示，就代表授權整份計劃**：執行中不要向我請求任何授權、確認或決定，也不要問我問題。
> - **不要停下來等我驗證**：所有檢查由你自己執行並記錄證據；需要我決定的事只列入最終彙報。
> - **有問題記錄下來就好**：記錄在 build-log，依 PLANS 的問題處理規則做最小修正，或隔離受影響的步驟，繼續其他可做的工作，最後統一彙報。不得把未驗證的項目宣稱為通過。
> - **每一步皆強制 commit**：每個步驟（包括執行中新增的修正步驟、計劃修訂，以及檢查失敗時保留證據的 checkpoint）完成檢查、更新 build-log 後都必須在本地 commit，成功後才進入下一步；不合併多步，也不得以未提交的修改結束。計劃檔一律提交，build/ 下的 phase 檔用 `git add -f`。
> - **不准切換或建立 branch**：只在 GUI 分支上工作；不建立、切換、刪除、重新命名 branch，不切到 detached HEAD，不建立 worktree，不 push。
>
> 這個請求授權整份計劃列明的全部工作，包括：
> - 計劃列明的程式與文件修改，以及本地 commit；
> - 以 Poetry 把 python-docx 與 lxml 加入 app，包括需要的 PyPI 連線；
> - 把 /home/minervamuses/論文/bime_word-1.1.5.zip vendor 到 app/vendor/bime-word；
> - 唯讀使用論文資料夾中的檔案，做試轉的副本；
> - 依 PLANS 在沙箱外執行完整測試。
>
> 不授權其他依賴、付費模型呼叫、push 或發佈，也不授權寫入我的論文資料夾或 ~/.claude/skills。需要保留的證據放在計劃目錄的 evidence/，不要只放在 /tmp。

第一個可執行的動作：[R1-S1](build/phase-1-preflight.md) 的唯讀核對。

- 還沒有任何實作證據時，從 R1-S1 開始。
- 中斷後要從哪裡恢復，只依 build-log 與實際的 Git 狀態決定。
