# 執行與續作入口

## 開始／續作

以下是使用者日後可以直接送出的啟動提示，不是撰寫階段的執行指令。

> **使用者端前提**（給使用者看，不是給執行者的指令）：
> - 執行者不會停下來等你，但宿主對沙箱外指令與連網的權限提示不受本計劃控制。如果希望啟動後離開、回來時已經跑完，請以不逐次詢問的權限模式啟動；否則執行會停在第一個需要額外權限的局部檢查，或第一次連網（R3-S1 的 `poetry add`）。
> - 執行可能因為用量上限而中斷；再次送出同一段提示即可續作。

> 執行 harness/plans/2026-11-07-citation-panel-revamp/ 計劃，一次執行到底。先讀適用的 AGENTS.md、[GOALS.md](GOALS.md)、[PLANS.md](PLANS.md)、[build-log.md](build-log.md)，再依 PLANS 的步驟前提讀取下一個可執行的 build 階段檔；遇到局部阻塞也要檢查可先做的獨立步驟。開始工作前，先唯讀核對目前的 GUI 分支、HEAD、工作樹，以及 Conda app 中的工具；以步驟 ID 對照已完成的步驟與 commit；保留與本計劃無關的既有工作。依 PLANS 的執行契約做事，並遵守以下要求：
>
> - **我送出這段提示，就代表授權整份計劃列明的工作**：不要為已授權工作重複請求確認；PLANS 的停止條件與成本上限仍然適用。遇到必須追加授權的工作，停止相應執行並在彙報列明，不自行擴張授權。
> - **GUI 驗收由我本人操作**：你完成實作、必要自動檢查與程式碼核對，交付手動 GUI 清單即可，不要停下來等我驗證。紀錄自動證據與尚未回報的 GUI 結果，不宣稱 GUI 已實測。
> - **依 D15 隔離問題並繼續獨立工作**：同一問題兩次聚焦修正失敗，只封鎖該問題與相依步驟、記錄 Blocked，繼續其他已滿足前提的工作。一次昂貴嘗試（依 D16 只指付費 API，例如 OpenRouter；本計劃不授權呼叫）失敗／無改善，或剩餘工作均被阻塞而沒有可執行的獨立步驟時，才停止整次執行並彙報。不得重置次數無限重試，也不得把必要自動檢查的失敗改成通過。
> - **每一步皆強制 commit**：每個步驟（包括執行中新增的修正步驟、計劃修訂，以及檢查失敗時保留證據的 checkpoint）完成檢查、更新 build-log 後都必須在本地 commit，成功後才進入下一步；不合併多步，也不得以未提交的修改結束。計劃檔一律提交，build/ 下的 phase 檔用 `git add -f`。
> - **不准切換或建立 branch**：只在 GUI 分支上工作；不建立、切換、刪除、重新命名 branch，不切到 detached HEAD，不建立 worktree，不 push。
>
> 這個請求授權整份計劃列明的全部工作，包括：
> - 計劃列明的程式與文件修改，以及本地 commit；
> - 以 Poetry 把 python-docx 與 lxml 加入 app，包括需要的 PyPI 連線；
> - 把 /home/minervamuses/論文/bime_word-1.1.5.zip vendor 到 app/vendor/bime-word；
> - 唯讀使用論文資料夾中的檔案，做試轉的副本；
> - 依 PLANS 做局部檢查，完整 Python、npm、cargo 套件各留至 R6 執行一次；超過十分鐘的命令及追加完整重跑仍需明確授權。
>
> 不授權其他依賴、付費模型呼叫、push 或發佈，也不授權寫入我的論文資料夾或 ~/.claude/skills。需要保留的證據放在計劃目錄的 evidence/，不要只放在 /tmp。

第一個可執行的動作：[R1-S1](build/phase-1-preflight.md) 的唯讀核對。

- 還沒有任何實作證據時，從 R1-S1 開始。
- 中斷後依 build-log、實際 Git 狀態及步驟前提續作；同一問題的嘗試次數保留，不因再次送出提示而歸零。
