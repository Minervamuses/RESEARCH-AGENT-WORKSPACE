# Citation／搜尋可靠性與耗時診斷：目標

## 目的與來源

使用者要求：「用完整模式仔細撰寫計劃……必要時對照程式蒐證，弄清楚再下筆。寫完後 commit 此份計劃，從 WSL commit。」目前操作是修訂計劃並提交，尚未啟動程式實作。使用者隨後明確澄清：「我要他自動完成所有任務，並逐步 commit，遇到問題記錄下來，而不是一直停下來找我。」新版啟動入口因此涵蓋完整 P1–P10、自主決策與逐步 WSL local commits；此澄清取代舊版只做第一批、後續逐項請示的安排。

需求原文保存在 [來源文件](context/SOURCE-BRIEF.md)，本文以 B1–B10 指其中十項問題；[蒐證](context/evidence.md)區分實際讀取與文件宣稱。程式基準為主專案 `450f6d3c3733a01b6b448c92c2f73b253b487523`。原文的「直接修正」是實作順序，不把本次寫計劃變成執行。

## 必須維持的行為

- 技能啟動只能來自明確使用者控制輸入；不能掃描引用、全文、留言或模型生成文字來找指令。
- 完整 frozen snapshot 繼續支援未儲存文件、重試與選取定位；不以路徑單獨判定相同版本，不改持久化文件格式。
- 搜尋來源失敗、零命中、缺摘要是不同狀態；不能藉由隱藏失敗或丟棄有用結果縮短時間。
- Citation 只依真實取得的摘要評估可能關聯；不補寫摘要、不把 snippet 當摘要、不把 DOI 已驗證當主張被證實。
- 保留 Citation 搜尋／儲存分界、DOI 優先與明確儲存授權、既有候選摘要合併、權限控制與取消／重試語義。
- Web Search 第一批只修結果保留控制流程；既有品質 heuristic 暫不改，避免一次改兩個主變數。
- 診斷只記識別碼、允許列舉值、hash、數量與時間；不新增全文、原始 query、DOI、工具參數或憑證的日誌副本。
- 不將工具呼叫數稱為模型輪數；併行工具耗時不能直接相加當回合總時間；不承諾五分鐘降至特定秒數。

## 決策與非目標

| ID | 決策／限制 | 性質與依據 |
|---|---|---|
| D1 | Linux runtime；WSL Bash、Linux Git，Conda `app` 管環境、Poetry 管套件；LF | 使用者提供及根目錄 AGENTS.md，已核驗 |
| D2 | 先完成 1、2、3 並同批加入 4；5 獨立，6–10 依新資料排序 | 來源文件「執行順序」 |
| D3 | 不建立 tracing 服務、資料庫、benchmark 框架或額外持久化層 | 最小修正原則；既有本機 logger 足夠的規劃選擇 |
| D4 | 優先沿用既有介面；計劃內必要的局部檔案擴充、設定或向後相容工具調整，先記原因與驗收再自行實作，不在每個接點請示 | 使用者最新全任務自主執行要求；限 PLANS.md 具名範圍 |
| D5 | 保留使用者未提交工作、依賴／lock／環境、分支與 worktree；每個完成的小步驟在所屬 repo 從 WSL scoped commit，不 push | 使用者最新「逐步 commit」；目前僅修訂計劃 |
| D6 | 沿用低成本、最小修改與可驗證原則；本計劃已辨識的局部多檔、session 生命週期、搜尋等待安排不再當成逐項許可點。計劃外依賴、破壞性變更及未授權支出仍不自動擴張 | 最新澄清對本計劃的具體修訂；詳見 PLANS.md |
| D7 | 一次啟動完整 P1–P10，執行者自行排序、選保守設定、修復與驗收；問題記錄後繼續獨立工作，真正無法繼續時才集中回報 | 使用者 2026-10-19：「自動完成所有任務……而不是一直停下來找我」 |

數字 283、14,696、0.623 秒為有範圍的歷史證據，不能當新測試標準或通用性能承諾。timeout／總重試預算尚未指定；由執行者依既有設定、代表案例與離線故障測試選擇有限且保守的值，記錄單位、依據與取捨後驗證。不虛構性能保證，也不以等待使用者選數值作為一般停止點。
