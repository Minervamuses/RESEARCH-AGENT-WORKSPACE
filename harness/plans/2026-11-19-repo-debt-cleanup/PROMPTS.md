# 執行與續作入口

## 開始／續作

以下是使用者日後可以直接送出的啟動提示，不是撰寫階段的執行指令。

> **給使用者的前提說明**（不是給執行者的指令）：
> - 執行者不會停下來等你，但宿主對沙箱外指令的權限提示不受本計劃控制。完整 pytest、`cargo test`、`poetry remove` 都需要在沙箱外執行。希望啟動後離開、回來時已經跑完，請以不逐次詢問的權限模式啟動；否則執行會停在第一個需要沙箱外權限的指令（C1-S2）。
> - 執行可能因為用量上限而中斷，再次送出同一段提示即可續作。
> - GOALS 的 P1–P3、P5、P8、P9、P12、P13 是計劃提出、你尚未逐項確認的做法。若要否決某一項，請在送出提示前修改 GOALS，或在提示末尾加一句，例如「P2 不做」。U1–U22 與 R1–R6 是你已確認的決策與否決項。

> 執行 harness/plans/2026-11-19-repo-debt-cleanup/ 計劃，一次執行到底。
>
> 先讀適用的 AGENTS.md、CLAUDE.md、[GOALS.md](GOALS.md)、[PLANS.md](PLANS.md)、[build-log.md](build-log.md)，再依 PLANS 的相依關係讀取下一個可執行的 build 階段檔；遇到局部阻塞時，先做其他前提已滿足的階段。開始工作前，先唯讀核對目前的 GUI 分支、HEAD 與工作樹，以步驟 ID 對照 build-log 與 git log 中已完成的步驟，並保留與本計劃無關的既有檔案。依 PLANS 的執行契約做事，並遵守以下要求：
>
> - **產品邊界優先。** 這是單人、本地、一次一個專案、一個對話、一個回合的工具。不為不支援的同時操作新增鎖、排程、全域控制器或衝突表；支援的循序使用中出現的錯誤，則一律當成缺陷處理。新增任何檢查或協調前，在 evidence 寫明它的觸發情境。遵守 U20–U22：既有 citation 不因同批新作品寫入失敗而失效、Busy 只集中重複判斷、UI 元件只共用語意相同的部分。
> - **我送出這段提示，就代表授權整份計劃列明的工作。** 不要為已授權的工作重複請求確認。需要追加授權的工作，停止相應部分，並在最終彙報列明。
> - **不呼叫任何付費 API。** 不得啟動會連 OpenRouter 的 CLI 或桌面 app；所有測試用假模型。免費的 Crossref、DataCite、doi.org 只可用於 C5-S6 的選擇性冒煙測試。
> - **GUI 驗收留給我本人操作。** 你交付清單即可，不要停下來等我，也不要宣稱 GUI 已驗證。
> - **隔離問題並繼續獨立工作。** 同一問題兩次聚焦修正失敗，只封鎖該問題與相依步驟，記錄為 Blocked，繼續其他已滿足前提的工作；剩餘工作全部被阻塞時才停止並彙報。不得把必要檢查的失敗改成通過。
> - **每一步皆強制 commit。** 每個步驟完成檢查、更新 build-log 後都在本地 commit，成功後才進入下一步；執行中新增的修正步驟、計劃修訂，以及檢查失敗時保留證據的 checkpoint 也一樣。只 `git add` 明確路徑，計劃 build/ 下的檔案用 `git add -f`；不得以未提交的修改結束。
> - **不准切換或建立 branch。** 只在 GUI 分支上工作；不建立、切換、刪除、重新命名 branch，不切到 detached HEAD，不建立 worktree，不 push。
>
> 這個請求授權：
> - 計劃列明的程式、skill 文字、測試與文件修改，以及本地 commit；
> - PLANS 所列的局部檢查與完整檢查（pytest、npm test、npm run build、cargo test --locked）；
> - C5-S5 以 Poetry 移除 pybtex（只限這一項相依變更）。
>
> 不授權：
> - 其他相依的新增、升級或移除；
> - 付費模型呼叫、push 或發佈；
> - 修改 for_agents/、AGENTS.md、CLAUDE.md、note/ 的既有內容（唯一的例外是依 GOALS 在本計劃決策紀錄末尾追加更正）、README 的「單一工作流程（產品限制）」一節、其他計劃、~/.claude/、我的論文資料夾、任何 RESEARCH.md、app/store/ 的資料或 cite/ 的殘留檔案。
>
> 需要保留的證據放在計劃目錄的 evidence/，不要只放在 /tmp。

第一個可執行的動作是 [C1-S1](build/phase-01-preflight.md) 的唯讀核對。

- build-log 還沒有任何實作證據時，從 C1-S1 開始。
- 中斷後，依 build-log、實際 Git 狀態與相依關係續作。同一問題的嘗試次數保留，不因再次送出提示而歸零。無法確認歸屬的修改要保留，並封鎖受影響的步驟；不因檔案在本計劃範圍內就整檔還原。

## 修訂

> 僅修訂此計劃，以納入我接下來的變更。讀 GOALS、PLANS、build-log 與受影響的階段，保留既有的完成證據與無關的需求，同步更新相依關係、驗收、S-ID 歸屬表與 plan-index.json。除非我另行要求開始，這次不修改產品程式碼。在本地提交計劃的修改，不 push，也不建立或切換 branch。

## 審查

> 唯讀審查此計劃。先依 CLAUDE.md 的審查規則，對每個被審查的機制說明它的觸發情境屬於支援的正常使用，還是不支援的同時操作。再對照 GOALS 的 G1–G9、U1–U22、R1–R6、P 項與 A1–A7，以及決策紀錄 note/20261119/citation_storage_unification_decision.md，檢查：
> - 每個目標是否有階段與可觀察的驗收；
> - S-ID 歸屬表是否與 GOALS 的範圍一致；
> - 相依關係與第一步；
> - 失敗與中斷時如何續作；
> - PLANS 的基線是否與目前程式相符；
> - 禁止付費 API、每步 commit、不碰 branch 是否一致。
>
> 回報具體的缺口或會誤導執行的地方。不支援的同時操作所引起的問題，只列出、不當成缺口。除非另有授權，不修改檔案，也不實作。
