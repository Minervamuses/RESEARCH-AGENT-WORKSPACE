# 詰問 skill、文體 skill 與文件 context：目標與決策

本檔記錄穩定的目標、範圍與決策。路線與執行契約在 [PLANS.md](PLANS.md)，狀態與證據只記在 [build-log.md](build-log.md)。

## 目的

1. 在桌面編輯器圈起一段文字、以 `@grill` 啟動時，agent 會先讀懂這段在主張什麼，再試著推翻它，只對有具體理由的地方提出反駁或問題；作者回應後重新檢查，直到通過。檢查期間不改文件。
2. 一個文體 skill 寫好論文、教材、筆記、計劃書、Abstract、Poster、投影片的格式與副檔名，並有每回合都生效的回覆規則。
3. 文件 context 不再隨回合累積：先量出文件佔多少，再讓舊回合不帶文件全文、同回合連續編輯不累積全文。

## 來源

- **S1**：`NOTES-grill-skill-and-document-context.md`（repo 根目錄，未追蹤，2026-11-14，對應 `GUI` `7489076`）。本計劃已把需要的內容寫進來，執行時不必依賴它。筆記中的【已定】、【提案】、【未定】標記照原樣沿用。
- **S2**：2026-11-14 撰寫計劃時，使用者對四個問題的回答（下表 U1–U5）。
- **S3**：撰寫時的讀碼結果，見 PLANS「基線」。

## 範圍

**範圍內**：上表目標；為此必要的測試與文件；`academic-paper-writing` 佔位符寫法的對齊（見 A4）。

**範圍外**：

- 執行者跑真實模型的詰問測試（U2）。框架做好，真實測試由使用者自己跑。
- 把 `~/.claude/skills/paper-writting` 搬進 agent（U4）。
- 改變「最近 10 回合」的設計、歷史保存格式、重試／凍結引用／還原提交狀態的行為（S1 三）。
- 大文件目錄化與按需讀取、依 token 控制歷史、Prompt Caching、歷史檔內文件去重、自動壓縮對話、把正在編輯的文件交給 RAG（S1 三「後續可做，現在不做」）。
- 擴充桌面編輯器支援的副檔名（目前只開 `.md`、`.markdown`、`.tex`，上限 1 MiB）或改變 Ask 權限下 bash 每次需核准的行為（D10）。
- 圈選修改與 skill 檢視的對象維持「當下開啟的那份文件」（D9）。
- 新增依賴、付費 API 呼叫、push、建立或切換 branch。

## 不變條件

- 歷史檔（conversation JSON）寫入的內容與格式不變；改的只有歷史進入模型時的組裝。
- 不帶 `@grill` 的文件回合：快照、`document_edit`、`bibliography_lookup`、強制 normal 模式都照舊。
- `document_edit` 仍只寫當前編輯器文件或凍結的文件引用，仍經版本檢查與權限核准。
- `app/rag/` 不放 agent 專屬行為。
- 回覆使用繁體中文的語言政策不變。

## 撰寫時採用的可逆假設

這些不是使用者的決定。最終彙報要列出，讓使用者確認或推翻。

| ID | 假設 | 理由 | 推翻時的影響 |
|---|---|---|---|
| A1 | 詰問回覆先列一段簡短的「還原」（論證結構），再列發現 | S1 指出「模型會不會真的做還原」是整個做法的前提；回覆中看得到還原，使用者跑真實測試時才能判斷 | 改 SKILL.md 輸出格式與評估報告欄位 |
| A2 | skill 名稱：`grill`（S1 已用 `@grill`）、文體 skill 為 `writing-genres` | 技能名稱沿用 kebab-case 慣例 | 改目錄名與測試 |
| A3 | 遮蔽以「啟用的 skill 包含 `grill`」判斷，用一個具名常數，不新增 manifest 欄位 | manifest schema 是 `extra="forbid"`，新增欄位要改 schema；目前只有一個需求，不做通用抽象（AGENTS.md） | 之後有第二個唯讀 skill 時再改成 manifest 欄位 |
| A4 | 缺內容的佔位符統一成 `bime_word` 認得的 `[TODO: …]`、`[CITE: …]`、`[FIGURE: …]`，新 skill 與回覆規則採用，`academic-paper-writing` 原本的 `[insert citation]` 等改成同一寫法 | S1 一「周邊事項」的提案；vendored bime_word 確實辨識這三種 | 回復 `academic-paper-writing` 一行說明與新 skill 的寫法 |
| A5 | 各文體的預設格式（例如投影片與 Poster 用 `.md` 或 `.tex` 哪一種）由執行者依編輯器支援與既有工具（Pandoc、bime_word）擬定 | S1 只定了「寫好格式與副檔名」，沒有給內容 | 改 skill 內容即可 |
| A6 | 回覆規則只寫跨文體、每回合都需要的少數幾條：先辨識文體再依該文體寫；需要細節時建議使用者以 `@writing-genres` 啟用；佔位符寫法；編輯器只能圈選修改 `.md`／`.markdown`／`.tex`；詰問與改寫分開 | S1 沒有列出規則全文；`SYSTEM_PROMPT` 每回合都送，越短越好 | 改 `SYSTEM_PROMPT` 一段文字與對應測試 |
| A7 | 文件佔比以「該次呼叫訊息中文件內容的字元數 ÷ 全部訊息字元數 × `input_tokens`」估計，並標為估計值 | API 只回總 input tokens；不新增 tokenizer 依賴 | 改量測欄位 |
| A8 | 「輕重」的暫定準則：只提會影響主張成立的問題，字面與風格不在詰問範圍 | 由 D4「只對還原失敗或推翻成功的地方開口」推出；S1 列為未解 | 依使用者真實測試結果修改 SKILL.md |
