# 執行與續作入口

## 開始／續作

以下是使用者日後可以直接送出的啟動提示，不是撰寫階段的執行指令。

> **使用者端前提**（給使用者看，不是給執行者的指令）：
> - 執行者不會停下來等你，但宿主對沙箱外指令的權限提示不受本計劃控制。希望啟動後離開、回來時已經跑完，請以不逐次詢問的權限模式啟動；否則執行會停在第一個需要沙箱外權限的指令（最晚是 K8 的完整 pytest）。
> - 執行可能因為用量上限而中斷；再次送出同一段提示即可續作。

> 執行 harness/plans/2026-11-14-grill-genres-document-context/ 計劃，一次執行到底。先讀適用的 AGENTS.md、[GOALS.md](GOALS.md)、[PLANS.md](PLANS.md)、[build-log.md](build-log.md)，再依 PLANS 的相依關係讀取下一個可執行的 build 階段檔；遇到局部阻塞時先做其他前提已滿足的階段。開始工作前，先唯讀核對目前的 GUI 分支、HEAD 與工作樹，以步驟 ID 對照 build-log 與 git log 中已完成的步驟，保留與本計劃無關的既有檔案。依 PLANS 的執行契約做事，並遵守以下要求：
>
> - **我送出這段提示，就代表授權整份計劃列明的工作**：不要為已授權工作重複請求確認。需要追加授權的工作，停止相應部分並在最終彙報列明。
> - **不呼叫任何付費 API**：不得以真實模型跑詰問評估（不得使用 `--live`），也不得啟動會連 OpenRouter 的 CLI 或桌面 app；所有測試用假模型。真實詰問測試與 GUI 驗收由我本人在交付後操作，你交付方法與清單即可，不要停下來等我，也不要宣稱它們已驗證。
> - **隔離問題並繼續獨立工作**：同一問題兩次聚焦修正失敗，只封鎖該問題與相依步驟、記錄 Blocked，繼續其他已滿足前提的工作；剩餘工作全部被阻塞時才停止並彙報。不得把必要檢查的失敗改成通過。
> - **每一步皆強制 commit**：每個步驟（包括執行中新增的修正步驟、計劃修訂、檢查失敗時保留證據的 checkpoint）完成檢查、更新 build-log 後都在本地 commit，成功後才進入下一步；只 `git add` 明確路徑，計劃 build/ 下的檔案用 `git add -f`；不得以未提交的修改結束。
> - **不准切換或建立 branch**：只在 GUI 分支上工作；不建立、切換、刪除、重新命名 branch，不切到 detached HEAD，不建立 worktree，不 push。
>
> 這個請求授權：計劃列明的程式、skill、測試、腳本與文件修改及本地 commit；PLANS 所列的局部檢查；K8 一次完整 pytest（改到前端或協定時加 npm、cargo 各一次）。不授權新增依賴、付費模型呼叫、push 或發佈，也不授權寫入 ~/.claude/、我的論文資料夾或任何 RESEARCH.md。需要保留的證據放在計劃目錄的 evidence/，不要只放在 /tmp。

第一個可執行的動作：[K1-S1](build/phase-1-preflight.md) 的唯讀核對。

- build-log 還沒有任何實作證據時，從 K1-S1 開始。
- 中斷後依 build-log、實際 Git 狀態及相依關係續作；同一問題的嘗試次數保留，不因再次送出提示而歸零。
