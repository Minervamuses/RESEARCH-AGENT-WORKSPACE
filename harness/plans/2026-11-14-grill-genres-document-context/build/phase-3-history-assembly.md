# K3 舊回合不帶文件全文

- **後置條件**：歷史進入模型時，較舊的快照與凍結引用全文換成佔位，僅保留最後提交的編輯器快照全文；保留快照不保證是最新存檔版本。保存的歷史、重試、凍結引用、還原提交狀態都不變；已封存的舊版本仍能依佔位取回。
- **涵蓋**：G7。
- **相依**：K2（量測函式與 15 回合測試）。
- **輸入**：PLANS「基線」的文件回合與歷史重播兩節；GOALS 的不變條件與範圍外項目。

## 行為規格

1. **只改組裝，不改保存**。`semantic_input` 照原樣寫進歷史檔；轉換只發生在把歷史做成模型訊息的時候。不改 `LATEST_CONTEXT_TURNS`。
2. **保留哪一份提交快照**：當前回合帶文件快照時，所有歷史回合的快照都換成佔位；當前回合不帶快照時（例如文件關閉後的普通對話），保留最近 10 個可入 context 回合中最後提交的編輯器快照全文，其餘換成佔位。`semantic_input` 保存的是提交時內容：若該輪把 A 編輯成 B，保存的快照仍可能是 A。模型可見的歷史快照須標明「最後提交的快照，不保證是最新存檔內容」，不能沿用「目前文件」的語意：把快照標頭 `[Current editor document snapshot…]` 換成標示最後提交快照的標頭，並拿掉 JSON 後面針對當前編輯器的說明（例如「Use this exact editor snapshot…」與「call document_edit…」），因為之後的回合未必有 `document_edit` 可用；只改模型組裝，不改歷史檔。當前回合只帶凍結文件引用、沒有編輯器快照時，視為「不帶快照」：歷史中最後提交的快照照樣保留，當前凍結引用另外照舊送出。本計劃不新增關閉文件後自動讀盤或狀態保存。「當前回合帶不帶快照」以當前回合實際送出的文字中有沒有快照標頭判斷（或由呼叫端明確傳入），不能依 `_document_turn_active`：重試與 `submittedContext` 回合會改用保存的 `semantic_input`，此時文字含快照但旗標可能為假（見 PLANS 基線）。
3. **佔位要留下的東西**：明確寫出「這是較早的版本，不是目前文件」；路徑、`editorRevision`、`diskFingerprint`；當時的選取範圍（行號與 UTF-16 範圍）；選取範圍明顯小於全文時保留選取的文字（上限由執行者訂一個合理值，並在 build-log 記錄這是可逆的選擇）；全文仍在對話封存中、需要還原或比較時可依封存提示取回（指出回合編號或可搜尋的識別資訊）。使用者打的字一律保留。
4. **凍結引用**：歷史中的每個引用保留 `referenceId`、種類、引用的段落文字與行號，只拿掉快照的 `sourceText` 全文；當前回合明確提供的凍結引用照舊保留，沿用既有同訊息去重。
5. **辨識失敗**：無法辨識格式的舊回合（例如本功能之前的格式差異）原樣保留，不丟例外；量測函式的 `document_parse_issue` 可用來發現這種情況。快照 JSON 要從標頭之後用 `json.JSONDecoder().raw_decode` 一類的方式取出，不依賴 JSON 後面的說明文字：K5 會改詰問回合的說明文字，而已保存的回合保留舊文字，兩種都要能辨識。
6. **產生與辨識共用同一組標頭常數**，避免 `service.py` 改了字串而重播端沒跟著改。模組依存方向依現有結構選擇；不要讓 `agent/session.py` 匯入整個 desktop service。
7. 所有把歷史送進模型的地方都走同一套轉換：`_base_prompt_history`（normal 模式，也被 `agent/thinking/orchestrator.py:188` 使用）、`_visible_context_text`（`agent/session.py` 約第 1096 行，由 `orchestrator.py:534` 以純文字送進 extended 模式提示），以及 K1 核對出的其他使用者（例如 `fixture_session.py` 若有自己的組裝，判斷是否需要一致）。`recent_turns` 等對外顯示用途不轉換。

K3 只驗收使用者訊息中的歷史縮減；工具結果由 K4 驗收。K3 完成但 K4 尚未完成時，整個 prompt 仍可包含多份工具結果全文，不能把 K2 的全文總副本數當作 K3 必須等於一的條件。

## 步驟

| 步驟 | 工作 | 必要檢查 |
|---|---|---|
| K3-S1 | 依上方規格實作轉換函式與單元測試 | 單元測試涵蓋：當前回合有快照、無快照、只有凍結文件引用三種情形；保留的歷史快照標頭已換成最後提交快照、編輯指示已移除；佔位內容（版本標示、路徑、revision、範圍、窄選取的文字、封存指引）；凍結引用保留段落文字；`sourceTextSameAs` 情形；快照後接舊說明文字與詰問唯讀說明文字兩種變體都能辨識；格式無法辨識時原樣保留 |
| K3-S2 | 接上所有歷史組裝處 | 在 K2 的 15 回合測試加入新斷言：每次模型呼叫中，當前回合帶快照時，較早使用者訊息的快照與凍結引用全文已換成佔位；無當前凍結引用時，僅就使用者訊息計數，編輯器快照全文只保留當前一份，不把工具結果算進此斷言。另測文件關閉後只保留最後提交的快照；用最後一輪由 A 存成 B、再關閉文件的案例，確認留下 A 且標明是提交快照，不冒稱已含 B，K2 的量測也仍能辨識並計入這份帶版本說明的歷史快照。歷史檔中各回合的 `semantic_input` 仍含完整快照（與保存內容逐字比對）；重試文件回合送出的仍是原 `semantic_input`，歷史舊快照照樣縮減；extended 模式的 `_visible_context_text` 同樣符合歷史縮減與版本標示。另跑 `tests/test_desktop_document_service.py`、`tests/test_session_persistence.py`、`tests/test_thinking_session.py`、`tests/test_desktop_fixture.py` 與 K1 列出的相關模組 |
| K3-S3 | 量測修改後的數字 | 以 `DOCUMENT_BUDGET_REPORT=<計劃>/evidence/K3-S3/after-history.json` 重跑 15 回合測試，摘要與 `before.json` 對照（第 1、5、10、15 回合），分開列出 current、history、tool_results；此步不要求工具結果全文減少，寫進 build-log |

各步驟各自 commit。

## 風險

- 模型可能需要已封存的提交版本來回答還原或比較請求：靠佔位中的封存指引；normal 模式可用 bash 取回（需核准），extended 模式不行（既有封存提示已說明）。未進入提交快照的中間存檔版本不保證可由此封存取回；實際取回行為放進 K8 的手動 GUI 清單，不由執行者宣稱已驗證。
- 若發現某個既有測試斷言舊回合必須含全文，先判斷那是保護「保存」還是「組裝」：保護保存的斷言不能改；只描述舊組裝方式的斷言可改，並在 build-log 說明。
