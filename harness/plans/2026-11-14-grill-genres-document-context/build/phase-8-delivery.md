## 最終彙報內容

1. 每個目標 G1–G9 的狀態與證據指向；Blocked 項目的原因與續作條件。
2. 文件 context 量測對照：before、after-history、after 三組數字（第 1、5、10、15 回合的全文副本總數、文件字元數與估計 token 佔比，當前快照／凍結引用、歷史與工具結果分開說明；連續兩次編輯那一回合的工具結果字元數），並註明是假模型與估計值。
3. K4 的出口決定與理由。
4. 請使用者確認或推翻的可逆假設 A1–A8，特別是：還原段是否要顯示（A1）、佔位符統一（A4）、七種文體的預設格式（A5）、回覆規則內容（A6）、輕重的暫定準則（A8）。
5. `@grill` 在段落留言中的實際行為（K5-S3）。
6. 使用者自行跑真實詰問測試的方法：放置真實段落的方式、`--live` 指令、預估模型回合數與費用提醒、如何填人工觀察表（含回應適用性、還原忠實程度、質疑有效性與未標註發現）。明寫「執行者沒有用真實模型測試過詰問」。
7. 手動 GUI 檢查清單（由使用者本人操作，執行者不宣稱已驗證）：
   - 開一份 `.md`，圈一段，輸入 `@grill 檢查這段`：回覆提供可供人工檢查的還原與有理由的發現，或說明資料不足／有範圍的通過；不能以格式符合當作詰問品質通過。沒有出現編輯核准；文件未變。
   - 下一回合不加 `@grill`、明確要求修改：照常出現編輯核准並能存檔。
   - 在段落留言寫 `@grill`：觀察是否啟用（對照 K5-S3）。
   - 同一份文件連續做十幾個編輯回合：檢查是否混淆版本；要求取回某個已封存回合的提交版本時，模型能依佔位從封存取回（會出現 bash 核准）。未進入提交快照的中間存檔版本不在此保證內。
   - 最後一輪將 A 編輯並存成 B 後關閉文件：普通對話只保留最後提交的 A 快照，明確標為提交時內容，不能冒稱它是最新存檔的 B；不把沒有自動載入 B 判為本計劃驗收失敗。
   - 以 `@writing-genres` 要求產出一份投影片或 Poster 原稿：寫出的副檔名與 skill 說明一致，`.md`／`.tex` 能在編輯器開啟。
8. 本計劃的 commit 清單（步驟 ID 對照），以及確認沒有 push、沒有建立或切換 branch。
