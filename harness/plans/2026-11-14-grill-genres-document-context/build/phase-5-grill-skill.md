# K5 詰問 skill 與唯讀文件回合

- **後置條件**：`app/skills/grill/` 寫好並被技能目錄載入；帶文件且啟用 `grill` 的回合，模型看得到文件快照，但 `document_edit` 不在可用工具中、說明文字不邀請編輯；`@grill` 只活一回合；`@grill` 寫在段落留言中的實際行為已測試並記錄。
- **涵蓋**：G1、G2。
- **相依**：K1。若 K3 已完成，測試要與新的歷史組裝一起通過。
- **輸入**：GOALS D1–D8、U4、A1、A2、A3、A4、A8；PLANS「基線」的文件回合與 Skill 兩節。

## SKILL.md 必須涵蓋的內容

用中文或英文寫皆可（與其他 skill 一致即可），但下列每一點都要有，且不得把做法寫成錯誤類型清單（D1、D3）：

1. **對象**：當前編輯器快照中的選取範圍，或使用者以引用／留言指定的段落。可用整份文件的上下文（圈選段落常依賴前文的定義或結果）；需要時可讀專案檔案與知識庫、查詢文獻庫或可用的網路來源來檢查概念。
2. **還原**（D4）：用白話把這段重寫成論證——要讀者相信什麼、每一句的角色（主張、理由、定義、觀察結果、假定）、誰支持誰；不沿用原文的術語與連接詞，每一步自己寫出來。寫不出來、看不出支持誰、或有兩種都講得通的讀法之處，就是第一批發現。回覆先列一段簡短的還原（A1），以固定的標題標示（例如 `## 還原`；發現區也用固定標題，例如 `## 發現`），讓 K6 能機械辨識。
3. **試著推翻**（D4）：對每一個環節依角色找不成立的情況——推論造反例；事實陳述查立足點（量到的、引用的、前文推出的，還是假定）；當成理由的概念用領域知識與可查的來源檢查是否為真、是否適用。不必事先知道問題屬於哪一類。
4. **提出**（D4、A8）：只對還原失敗或推翻成功的地方開口。每一條含原文位置（逐字引用原文的字句，引用格式要固定，讓 K6 能機械比對）、具體理由（反例、缺的那一步、與文件哪裡衝突、來源怎麼說）、要作者回應什麼。有理由時提反駁，無從判斷時提問題（例如只有作者知道的實驗結果，就問從哪裡來）；沒有具體理由的質疑不提；字面與風格不在詰問範圍。
5. **作者回應之後**（D5）：把回應放回還原，再試著推翻一次。補上缺步 → 要求寫進文字（讀者看不到這段對話）；只是換說法 → 問題維持；指出反駁有錯且給了理由或來源 → 撤回。作者堅持但沒有新理由時不放行。
6. **通過**（D6）：還原得出來、每個環節都找不到不成立的情況，就明確說「通過」；沒問題的段落第一輪就應通過，不為了有話說而硬挑。
7. **不改文件**（D8）：只檢查不改寫；缺的內容只以 `[TODO: …]`、`[CITE: …]`、`[FIGURE: …]` 的形式在回覆中建議（A4），由作者通過後另行改寫。潤飾字面不在本 skill 範圍。
8. **一回合**（D7）：每回合需重新輸入 `@grill`；上一輪的發現從對話歷史接續。
9. **邊界**：作者研究細節模型不知道時，只能讀專案檔案或檢查文字有沒有交代立足點；每條反駁都附理由，讓作者能反過來檢查它。

是否需要 `manifest.yaml`：依 K1 核對的技能載入規則決定；不需要額外工具時可以不宣告 `tools`（沒有 `tools` 段時沿用 normal 模式工具）。

## 步驟

| 步驟 | 工作 | 必要檢查 |
|---|---|---|
| K5-S1 | 寫 `app/skills/grill/SKILL.md`（必要時加 manifest） | 依上方九點逐項核對並在 build-log 列出每一點對應的段落，並記下 SKILL.md 實際採用的還原與發現標題、引用格式；技能探索測試（沿用 `tests/test_skills.py` 或 `tests/test_inline_skills.py` 的方式）確認 `grill` 被載入且 `@grill` 能被解析為行內引用 |
| K5-S2 | **拆開「可讀文件」與「可編輯」**：啟用的 skill 包含 `grill` 時（以一個具名常數判斷，A3），即使帶文件也不把 `document_edit` 加進有效工具，並確保它不會經由其他途徑出現在該回合的工具中（建議在 `tool_access_resolution` 加入強制工具之後再移除，一處同時涵蓋 PLANS 基線列出的三個使用點）；`service.py` 的快照說明與凍結引用說明改成唯讀版本（說明本回合是詰問檢查，不能編輯），其餘文件回合的說明不變。`bibliography_lookup`、強制 normal 模式照舊。回合結束後旗標與思考模式照常復原 | 新測試（假模型）：帶文件＋`@grill` 的回合，模型收到快照；綁定的工具不含 `document_edit`；工具可用性提示中 `document_edit` 不在 `available_tools`，只出現在 `unavailable_tools`（沿用共用的 `render_tool_availability_block`，不另做隱藏）；快照說明是唯讀版本；即使假模型硬發出 `document_edit` 呼叫，也不會產生候選或寫檔；同一 session 的下一個不帶 `@grill` 的文件回合，`document_edit` 回來、說明恢復原樣；`grill` 與另一個 skill 同時啟用時仍遮蔽。既有 `tests/test_desktop_document_service.py`、`tests/test_tool_access_matrix.py`、`tests/test_inline_skills.py` 通過 |
| K5-S3 | **段落留言中的 `@grill`**：寫測試，送出一個段落留言內含 `@grill` 的回合，觀察 skill 是否啟用 | 記錄實際結果。會啟用：保留測試作為回歸保護。不會啟用：測試改為斷言目前的實際行為並加註解，原因與可行的改法寫進 build-log，列入最終彙報；本計劃不為此改前端或協定 |

各步驟各自 commit。

## 交付給後續階段

`grill` skill、遮蔽行為與測試、留言觸發的實際行為。K6 依 SKILL.md 中固定的還原標記與引用格式寫機械檢查。
