# K6 詰問評估框架

- **後置條件**：有案例格式、合成示範案例、評估腳本與報告格式；腳本預設不呼叫付費模型，加明確旗標才連 OpenRouter；以假模型跑通；使用說明寫好，使用者可放入自己的真實段落後自行執行。
- **涵蓋**：G3。
- **相依**：K5（腳本走 `grill` 的實際路徑，並依 SKILL.md 的還原標記與引用格式做機械檢查）。
- **輸入**：GOALS U2、「未解決、但不阻塞本計劃的事項」；S1 一「還沒解決的」。

## 嚴格限制

執行者在本階段不得以真實模型執行腳本，也不得啟動會連 OpenRouter 的任何程式。所有驗證用假模型。

## 規格

1. **案例格式**（建議 JSON）：每個案例有 `id`；`kind`（`flawed` 或 `clean`）；`source`（`synthetic` 或 `real`）；`document`（整份上下文文字，Markdown）；`selection`（`document` 中逐字存在的段落）；`known_issues`（每條有 `id`、原文引用、說明；`clean` 案例為空）；`author_turns`（腳本化的作者回應，每條有 `type`：`rephrase`（只換說法）、`supply_step`（補上缺步）、`valid_rebuttal`（指出反駁有錯並給理由），以及預期：`maintain`、`request_write_in`、`withdraw`）。
2. **示範案例**：建議放 `app/tests/fixtures/grill/cases.example.json`。至少 3 個 `flawed`（例如推論跳步、把假定當事實、拿不適用的概念當理由，各一）與 2 個 `clean`，全部標為 `synthetic`，內容由執行者自行撰寫，不取自使用者的論文資料夾。檔頭或說明寫清楚「示範用，不能代表真實論文的測試結果」。
3. **腳本**（建議 `app/scripts/grill_eval.py`）：
   - 參數：`--cases <路徑>`、`--out <目錄>`、`--live`、`--max-rounds <n>`。
   - 走和編輯器相同的生產路徑（桌面服務的文件回合：開啟文件、`documentContext` 範圍等於 `selection`、輸入含 `@grill` 與對應 `skillReferences`），讓遮蔽與快照說明都被涵蓋；模型以可注入的工廠建立，測試注入假模型。
   - 沒有 `--live` 時拒絕建立真實模型，印出原因並以非零結束碼結束。有 `--live` 時，開跑前印出案例數與最多模型回合數（案例數 × (1 + 作者回應數)，上限 `--max-rounds`），提醒會產生 OpenRouter 費用。
   - 文件放在 `--out` 下的暫存工作專案中，不碰案例原檔；結束後確認文件內容未被改動。
4. **報告**（每個案例一份 Markdown＋一份 JSON，加一份總表）：每一輪的模型回覆全文、該輪呼叫過的工具名稱；機械檢查——回覆是否含還原段（依 SKILL.md 的標記）、每條發現引用的原文是否逐字存在於 `selection` 或 `document`、`clean` 案例第一輪是否宣告通過、幾輪後通過或達上限、全程有無 `document_edit` 呼叫、文件是否未變；以及一張**留給使用者人工填寫**的表：每個已知問題是否被找到、有無硬挑、作者回應後的處理是否符合預期。報告不得自動判定語意上「找到了」。
5. **使用說明**（建議 `app/skills/grill/README.md`）：案例格式、如何放入自己的真實段落（建議放在 repo 外或不提交的位置，避免把未發表內容提交）、執行指令、成本提醒、如何讀報告，以及這套框架要回答的四個問題：會不會做還原與推翻、找不找得到已知問題、會不會硬挑沒問題的段落、多輪後會不會變軟與要幾回合。

## 步驟

| 步驟 | 工作 | 必要檢查 |
|---|---|---|
| K6-S1 | 案例格式、格式驗證與示範案例 | 測試：示範案例通過格式驗證；`selection` 不在 `document` 中、`kind` 與 `known_issues` 矛盾、未知的 `type` 都被拒絕並給出清楚訊息 |
| K6-S2 | 腳本與報告 | 假模型測試：沒有 `--live` 時不建立真實模型且結束碼非零（以注入檢查確認沒有建立 OpenRouter 用戶端）；假模型對一個 `flawed` 案例回覆含還原段與一條逐字引用、一條非逐字引用，報告正確標出兩者；`clean` 案例第一輪宣告通過被記錄；作者回應依序送出、輪數正確；全程無 `document_edit`、文件未變；報告含人工填寫表 |
| K6-S3 | 使用說明，並以假模型對示範案例完整跑一次 | 把假模型產生的示範報告存到 `evidence/K6-S3/`，在 build-log 明寫「假模型輸出，只證明流程」 |

各步驟各自 commit。

## 交付給後續階段

腳本、示範案例、使用說明與示範報告。K8 的最終彙報附上使用者自行跑真實測試的指令與成本提醒。
